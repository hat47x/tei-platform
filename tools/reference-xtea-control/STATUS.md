# 現状と引継ぎ

X-TEA制御面の現在地を、到達済みの経路と残作業の性質に分けて示します。詳細なコマンドは[README.md](README.md)、入口の一覧は[ROUTES.md](ROUTES.md)を参照してください。

## 到達したゴール

TEIの参照モデル再現確認で必要になるX-TEAの入力・観測を、GUIの座標操作に依存せず、生成AIが同じ手順で再実行できる状態になりました。

- Modeler / Editor / Driverは、起動時JavaエージェントとシナリオJSONで操作する。
- `.xead`は`xtea_cli.py`で直接読み、テーブル・フィールド・キー・機能・入出力・呼び出し関係をJSONで取得する。
- 実行した版、コマンド、結果、未確認事項を残せる。
- 別の担当者は`verify_driver.py`でDriverのビルド・合成試験・実動試験を再実行できる。
- XeadServerはTEIの参考対象外とし、この制御面の対象に含めない。

## 到達済みの経路

| コンポーネント | 確認済み | 主な証拠 |
| --- | --- | --- |
| Modeler | 読み取り、About、システム名変更と保存、テーブル名変更・追加と保存、フィールド名変更・追加・削除・型変更・並べ替えと保存、バックアップ | `scenarios/modeler-*.json` |
| Editor | 読み取り、システム名変更と保存、テーブル名変更と保存、テーブル一覧から編集画面を開く、テーブル追加・削除、機能追加・機能ID変更と保存、バックアップ | `scenarios/editor-*.json` |
| Driver | ログイン、XF100、XF300、XF200の更新・作成・削除、失敗時rollback | `scenarios/driver-*.json` |
| モデルCLI | システム、テーブル、フィールド、キー、機能種別、入出力CRUD、呼び出し関係、2モデルの差分、参照検査、JSON Schemaの出力 | `xtea_cli.py`、`tests/test_model_cli.py` |
| XeadServer | **対象外**。`xtea_server.py`と`server-harness/`は過去の参考資産 | `tests/test_live_*.py`、`tests/test_tomcat_war.py` |

`verify-all.ps1`の既定実行ではSwing E2E 12件とモデルCLI 8件を確認します。XeadServerの参考試験は`-IncludeXeadServer`を付けた場合だけ実行し、TEIの比較・受入には使いません。

## Driverの合成モデルによる検証

`tests/test_live_driver.py`は、元の配布Driverと合成モデル・使い捨てH2で8機能タイプとスクリプトUIを確認します。XF000はコンソールの開始・未実行終了、時刻指定の予約開始・停止・即時実行も対象です。予約時刻への到達による自動実行、反復なしの自動停止、反復ありの次回予約と手動停止も対象です。翌日の2回目の実行・長期反復・休日判定は未確認です。本来のログイン・メニューや参照モデル本体の全経路の受入確認ではありません。実行条件と確認内容は[README](README.md#driverの主要操作を再実行する)と[ROUTES](ROUTES.md#各機能タイプの実動試験)を参照してください。`verify_driver.py`はビルド後に棚卸し2件・結果記録3件・Swing統合12件・Driver実動52件を順に実行します。失敗した時点で打ち切り、XeadServerは含みません。`verify-all.ps1`にはDriverの追加試験を含みません。

結果は実行ごと・試験1回ごとに保存し、`summary.json`で成功・失敗・skipを区別します。失敗直後の画面・表の値・操作トレースも、後片付けより前に保存します。2026-10-22に観測した断続的な入力・複写失敗は原因未特定です。専用画面での再実行成功を、その原因の修正や共有デスクトップ・Windowsでの安定性の証明とは扱いません。

Script UIはダイアログ単体に加え、合成XF100からのチェックリスト・入力・オプション呼出し、結果による検索行の変化、取消・空選択時の元の条件維持、再表示、複数項目フォームを検証対象に含めます。リストの項目名とチェック状態を観測でき、項目順を固定せず操作できます。XF200の編集欄からScript入力・XF100選択一覧を開く経路も対象に含め、戻り値の画面反映、保存前のDB不変、保存後の値と更新カウンター、編集画面を閉じる取消を照合します。実参照モデルのScript実行とは区別します。

親Scriptと子編集画面の呼出し連鎖では、子の保存・閉じると親のcommit・rollbackの四つの組合せも検証します。子で保存済みの変更は親のrollbackで戻らず、子を閉じても親の未確定変更が自動的にrollbackされるとは限りません。画面上の取消とDB確定を別に扱います。詳しい観測表は[確定境界](ROUTES.md#呼出し連鎖と確定境界)を参照してください。

`instance.callFunction`での四つの組合せでは、子の戻りMapが親へ引き継がれることも照合します。さらに、XF100一覧の閉じる・XF290/XF390のPDF出力の正常終了が、親の未確定変更まで確定する三つの合成経路を確認します。読取りの画面でも、接続全体に対して無作用とは限りません。親のrollback後もDB変更と生成済みPDFが残るため、戻りコード・DB・外部出力を別々に観測します。

宣言型CHARのキーを、物理型CHARとVARCHARの二つの合成テーブルで検索する回帰試験も含めます。行が存在していても、型不一致と空白埋めによって検索が0件になる経路を確認します。元Scriptを合成データで実行するときも、型を合わせた入力条件と、原モデル全体の受入を区別します。

制御面MVPの完了判定と、追加のDriver経路試験、実参照モデルの意味の受入は別の判定です。試験件数やCIの成功だけで、これらをまとめて完了としません。

## 残作業の性質

残作業は、制御面の未実装ではなく、次のいずれかに分類できます。

1. **元のUIに存在しない操作**
   - XF200の登録・更新・削除は操作時に確定し、利用者が任意に実行するトランザクションrollbackボタンはありません。
   - 失敗時の内部rollbackは確認済みです。
2. **TEIの参考対象外**
   - XeadServerは対象外です。`DBMethod` / `Service` / WAR / Tomcat / JNDI / 認証は、TEIの比較・受入・新規検証に使いません。
   - 既存のコードと試験は過去の調査資産であり、`-IncludeXeadServer`を付けた場合だけ参考実行します。
3. **確認済みの要素操作**
   - Modeler: テーブル名変更・追加、フィールド名変更・追加・削除・型変更・並べ替え。
   - Editor: テーブル名変更・追加・削除、機能追加・機能ID変更。
4. **別Issueの機能移植**
   - Editorの要素並べ替え・一括置換は、モデル全体の操作として未確認です。#1802配下の機能移植として扱います。
   - Editorのフィールド一覧は`Field` / `TableField`の版差により空になります。GUI互換修正は上流変更になるため#2199はnot plannedとし、フィールド情報の取得はモデルCLI、編集はModelerで代替します。
   - 追加したテーブルのフィールド・主キー設定は未確認です。

## 完了判定

Issue #2152の制御面MVPは、次の条件で完了とします。

- Modeler / Editor / Driverの主要入口を、AIがシナリオJSONで再実行できる。
- 主要な書込み（保存、テーブル・フィールド・機能の追加削除変更、DriverのCRUD）を、使い捨てデータで確認できる。
- `.xead`の構造・機能・入出力・差分・参照整合性を、GUIなしのCLIで取得できる。
- 実行した版、コマンド、結果、未確認事項を残している。
- XeadServerは対象外として明示している。

次は完了に含めません。

- TEIのCanonical意味や業務上の等価性の判定。
- 4アプリの全ダイアログ・全条件分岐の実行。
- 実業務DB、本番デプロイ、認可。
- Editorの要素並べ替え・一括置換と、追加テーブルのキー設計。

## 引継ぎの入口

1. [README.md](README.md)の「使い方」と「一括検証」を読む。
2. `upstream.json`の版を確認し、`clone-xtea`でX-TEAソースを取得する。
3. Driverの検証はREADMEの環境変数を設定して`python verify_driver.py`を実行する。既存の`verify-all.ps1`はSwingの基礎試験用で、Driverの追加試験は含まない。
4. 変更したら`README.md`と`ROUTES.md`を更新し、実行した版、コマンド、結果、未確認事項をPRへ書く。

画面キャプチャには参照モデルの内容が含まれ得ます。公開時は#941の条件に従い、`build/`と`artifacts/`をコミットしません。
