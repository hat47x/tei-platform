# E0実測タスク — 初見参加者用（First Model Change）

**参加者に渡すのはこのページとTEIの通常のGetting Startedへのアクセスだけです。** 正解の編集差分、既存回帰テスト、観測担当者向け採点ルールを事前に示しません。セッション開始前に作業開始Git SHAとOS/Go環境を観測者が記録します。

## 状況

TEIを初めて使用する担当者として、`examples/first-workspace` を別の作業用ディレクトリへコピーしてください。元のRepository内容は変更しないでください。対象には業務の受付要求（Request）と、それを利用するApplicationが定義されています。

## 依頼内容

1. このWorkspaceをTEIのCLIで検査し、現在定義されている業務データの識別子と属性、依存するApplicationを確認してください。
2. 受付要求に**優先度（priority）**をコード型の属性として追加してください。元からあるデータとApplicationの識別子は維持します。
3. 変更した定義がTEIに反映されたことを確認し、「変わった箇所のSourceファイル」と「Canonicalに追加された意味」を説明してください。
4. 優先度の属性で存在しない型を意図的に指定し、CLIに検出させてください。出力からどこを直すべきか判断し、元の正しい状態へ復帰してください。
5. 最後に、**今回の操作だけで業務データの永続化や画面表示まで動くのか**を説明してください。不明なら推測せず「未確認」と答えてください。

途中で環境やコマンドの使い方が不明になった場合は、そのまま実際の操作として扱ってください。観測者は危険操作の停止やアクセス権の回復以外でヒントを与えないことを原則とします。終了時に、成功、失敗、未完了のどれだったかを参加者自身が報告します。報告はツールの`qualification`に反映されません。

## Agent参加者への制約

初見AgentへRepo内部の正解コード片や本タスクの回帰テストを貼り付けないでください。Agentが自ら検索・参照して見つけた情報は通常の活動として記録します。既存会話や学習済みプロンプトが実質的に解法を共有している場合は「初見」として扱わず、環境記録に明記してください。
