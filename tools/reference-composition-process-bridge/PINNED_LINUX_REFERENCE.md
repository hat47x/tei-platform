# Linuxで実行内容を固定する参照試験（Issue #1370）

この試験は[合成基盤とプロセスプラグインの接続試験](README.md)の補助検証です。製品の実装や正式なプラグイン契約は変更しません。

## 問題と検査方法

従来の成果物検証では、SHA-256を照合してからパスを指定して起動します。この二つの操作の間に、参照先が別のファイルへ置き換わる可能性があります。

Linux向けの`pinned_launch_linux_test.go`では、ホスト専用の一時ディレクトリへ実行ファイルを複製し、複製した内容のSHA-256を検証した後で書込み用ファイル記述子を閉じます。読み取り専用の記述子を開いてファイル名を削除し、子プロセスの起動時にその記述子を渡します。元のファイル名ではなく、保持したファイルを起動する方法です。

独立参照プラグインから内容の異なる実行ファイルを二つ構築して、元ファイルの置換とシンボリックリンクの付け替え後にも、検証済みの内容だけが起動することを確認します。誤ったSHA-256、別パスの指定、保持した記述子の解放後、開始前の中断は拒否します。既存の`DeploymentExecutor`を使い、検証器と起動器の両方に同じ保持済み実行ファイルを与える試験です。

```sh
go test -count=1 -run '^TestLinuxPinnedProcess' ./tools/reference-composition-process-bridge
```

## 保証していないこと

これは**LinuxでネイティブのGo実行ファイルを起動する参考実験**です。署名や来歴の真正性、OSによる隔離、ホスト自身の耐改ざん性を提供しません。ホストと同じ利用者権限で別のプロセスがホストに干渉できる環境での安全性も保証しません。試験用起動器に出力・資源管理等の製品要件が揃っているわけではありません。

通常の製品用プロセス実行器はこの試験で変更していません。Linux以外の実行先へ仕組みを一般化せず、実行先ごとの権限境界と成果物の固定方式を検証する必要があります。正式な契約と実行権限の移行は[ADR-0032](../../plan/adr/0032-composition-kernel-replacement.md)と[Issue #951](https://github.com/hat47x/tei-platform/issues/951)に従い、第二の契約解決機構を作りません。
