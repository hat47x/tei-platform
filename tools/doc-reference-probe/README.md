# 文書中のパス参照検査の試作

Issue #2309 の検討用です。任意実行であり、CIや統合条件には使いません。既存の `repository-plan-check` が扱うMarkdownリンクではなく、バッククォートで囲んだリポジトリルート相対パスを試します。Python 3.10以降を使います。

```bash
python3 tools/doc-reference-probe/probe.py docs/README.md
python3 -m unittest discover -s tools/doc-reference-probe -p 'test_*.py'
python3 tools/doc-reference-probe/evaluate.py
```

`repo-path-v2` は `docs/`、`plan/`、`tools/`、`reference/`、`requirements/`、`product/` のいずれかで始まるASCIIパスを抽出し、ファイルシステム上の存在を厳密に照合します。それ以外の明示宣言は対応外として報告します。Linuxでの実行を想定し、大文字小文字の区別はファイルシステムに依存します。出力には規則、照合方式、文書、抽出数と行ごとの結果を含めます。コードフェンスや例文も除外しないため、結果を人が確認する必要があります。

- `` `ref:docs/example.md` `` は明示参照です。`plan/`以外では未解決をエラー、`plan/`では警告にします。
- `` `planned:docs/example.md` `` は `plan/` 内のみで将来のパスを宣言します。対象が存在するようになれば警告します。
- `` `docs/example.md` `` は暗黙の候補で、未解決でも警告です。記法外の一般語は調べません。
- バッククォートで閉じた `ref:` / `planned:` の宣言が対象外の接頭辞や文字を含む場合は、見逃さずエラーにします。閉じバッククォートのない不完全な記法は検出できません。

明示参照の一時的な例外だけを、任意の `--allowlist path.json` で指定できます。

```json
{"baseline_count": 1, "entries": [{"document": "docs/example.md", "name": "docs/missing.md", "reason": "移行中", "issue": 2309, "expires": "2027-01-01"}]}
```

各項目は文書と名前の完全一致、理由、正のIssue番号または期限（両方も可）を要します。ワイルドカード、重複、項目数の `baseline_count` 超過は拒否します。対象文書内の明示未解決のみ警告に下げ、期限切れ・対象の削除や解決済み項目はエラーです。期限は実行環境のローカル日付で判定します。`--audit-allowlist` を併用すると、例外が登録された全対象文書を読み、期限切れ・不要項目をまとめて検査し、文書の消失・読取不能もエラーにします。指定しない場合は選択文書のみを検査します。

`--baseline-allowlist <基準版JSON>` を併用すると、現在の項目数が基準版の実際の項目数を超える場合、上限が基準版より増えた場合、基準版にない文書・名前の組が追加された場合にエラーにします。同数の項目差替えも検出します。理由・Issue・期限の変更は同じ項目として扱い、削除済みの基準項目の再追加は防げません。基準版を自動取得・固定する機構はなく、信頼できる版を利用者が選ぶ必要があります。基準版を指定しない実行では、ファイル内の上限だけを検査します。

`evaluate.py` は実際の `docs/README.md` の一箇所を明示・暗黙の参照それぞれで改名し、別に架空パスと一般語を追加します。計画中と未宣言の比較は合成文書で行います。基準main `497b63bf` の同文書で実在を確認した6種類・7出現を固定した正解集合として、未解決と判定された数も測ります。出現数が変われば正解集合の再確認を要求します。

2026-11-02、Ubuntu 22.04からWindows上のworktreeを参照した単回実行では、注入した明示パス欠陥2件中2件を検出、暗黙の改名1件を警告、一般語による追加候補は0件、5回の検査は約205msでした。正解集合7出現の偽陽性は、元の暗黙記法で0件、同じ文書をメモリ上で明示記法に置換した場合も0件でした。時間は欠陥注入の5検査のみで、正解集合の2検査は含みません。元文書の候補8件の残り `docs/audits/` 1件は意図が未判定のため正解集合から除外しています。計画中宣言ありは情報、宣言のない参照は警告でした。少数のパスに限るため、一般的な検出率・偽陽性率や人手の負担を示すものではありません。

この試作には基準版の自動固定、型・関数・コマンドの解決、すべての対象外記法の検出、十分な欠陥注入による検出率と偽陽性率の評価がありません。対象パスが存在しても記述の意味や実装状態の正しさは証明できません。宣言済み参照に偽陽性が残る、または人手の確認が効果を上回る場合は失敗の対象を縮小するか撤回します。
