# reference-ddl-entry（#1803）

一つのデータベースの物理対応から、提供元（Provider）が出力できるDDLを表ごとに取り出す入口です。データベースにも、Workspaceにも書き込みません。

~~~text
go run ./tools/reference-ddl-entry/cmd/tei-ddl-entry -workspace reference/workspace -database sales_core
~~~

## 位置づけ

このツールはSQLの文法を持ちません。物理対応から望ましい物理の形を導き、空の状態との差分にして、提供元のレンダリング（`migration.Render`）へ渡します。SQLの組み立ては提供元の責務のままです（ADR-0015）。

出力は、宣言された物理対応から導いた**新規作成用**のDDLです。既存のデータベースへの移行文ではありません。

## 守っている境界

- 表ごとに提供元へ渡し、出力できた表（`tables`）と、提供元が出力できなかった表（`unresolved`、理由つき）を分けて返します。一つの表の拒否が、他の表を隠しません。
- 提供元が拒否した内容を、このツールで補いません。

## 現在分かっていること

PostgreSQLの提供元は、新規作成する表の**主キー**を、列の追加の後に`ALTER TABLE ... ADD PRIMARY KEY (...)`として出力します。名前は付けず、PostgreSQLが決めます（[設計案](../../plan/design/POSTGRES_CONSTRAINT_RENDERING_DESIGN_2026-10.md)の案C）。`reference/workspace`の`sales_core`は、二つの表とも出力できます。

一意制約と外部キーも、**同じ差分で新規作成する表に限って**出力します。物理対応が名前を持てばその名前を使います。持たなければ、物理の実現の方針（ADR-0013）が決めた名前を付けて、常に`ADD CONSTRAINT <名前>`で出力します。名前の規則は[設計案](../../plan/design/POSTGRES_CONSTRAINT_RENDERING_DESIGN_2026-10.md)の4.2にある仮決めです。生成した名前が他の名前と衝突する表は出力せず、`unresolved`に理由つきで出します。順序は、表と列、主キー、一意制約、外部キーです（外部キーは、参照先の表が作られた後に出します）。外部キーの参照先のスキーマが決まっていない場合は、検索パスに任せず、拒否します。

このツールは空の状態との差分だけを扱うので、既存の表への追加は出ません。提供元は、既存の表への主キー・一意制約・外部キーの追加を、既存データの件数を観測した場合に限って出力します（`RenderMigrationSQLWithObservation`と`ObserveConstraintData`。[設計案](../../plan/design/POSTGRES_CONSTRAINT_RENDERING_DESIGN_2026-10.md)の4.4）。観測がない場合は`unresolved`、違反する行がある場合は件数を示して拒否します。既存の主キーの置き換え（P5、4.5）は、カタログから観測した制約名で`DROP CONSTRAINT`し、同じ文で新しい主キーを付けます。新しい列の重複・NULLの件数を数え、観測がなければ`unresolved`、参照する外部キーがあれば名前を示して拒否します。主キーをなくす変更も、観測した制約名で`ALTER TABLE ... DROP CONSTRAINT <名前>;`を出力します。観測がなければ`unresolved`、参照する外部キーがあれば名前を示して拒否し、`CASCADE`は使いません。

名前だけが違う場合（仮決め。[#2308](https://github.com/hat47x/tei-platform/issues/2308)、設計案4.2）: 物理対応が**宣言した**一意制約・外部キーの名前が、観測した名前と違う場合は、差分が`rename-constraint`になり、提供元は観測した名前から`ALTER TABLE ... RENAME CONSTRAINT <観測した名前> TO <宣言した名前>`を出力します。適用の直前の観測で、観測した名前が今もあり、新しい名前が空いている場合に限ります（空いていなければ`constraint-rename-name-taken`、観測がなければ`unresolved`）。実現が**生成した**名前（名前を宣言しない定義）は、観測した名前と違っても比べません。主キーは無名のままで、改名しません。

## 実データベースでの確認

`TEI_TEST_POSTGRES_DSN`を設定すると、出力した手順（`script`）を実際のPostgreSQLで実行し、観測した構造と宣言の差分が空になるかを確かめる試験が動きます。未設定の場合は skip されます。試験ごとに使い捨てのデータベースを作り、終了時に削除します。

- `reference/workspace`の`sales_core`: 実行後の差分が空。主キーの名前は、PostgreSQLが決めた`order_lines_pkey`、`orders_pkey`として観測された。
- 合成の親子の表（一意制約は名前つきと名前なし、外部キーは名前つき）: 実行後の差分が空。表名の順では子が先になるが、外部キーは最後に作られ、実行できた。
- 名前を持たない一意制約（複数列、宣言順が列名順と異なるもの）と外部キー（複数列）、多バイトの表名: 名前つきの新しいDDLで作ったデータベースと、名前を除いた以前のDDLで作ったデータベースの両方で、差分が空になり、観測した制約名が生成した名前と一致した。差分は構造だけを比べるため、名前はカタログから直接確かめている。
- 63バイトを超える生成名: 新しいDDLで作ると、差分が空になり、観測した名前が生成した名前（ダイジェスト付き）と一致した。以前の名前なしのDDLで作ったデータベースでは、PostgreSQLが別の切り詰め方をするため名前が一致しない（確認していない）。
- 実行前の比較が非空であることも確かめ、比較が何も見ていないために空になる事態を避けている。
- 既存の表への制約の追加（`existing_realdb_test.go`）: 新規作成の手順から制約の文を除いて表を作り、行を入れてから、提供元の観測と出力を通す。違反がない行では、主キー・一意制約・外部キーが追加され、実行後の差分が空になった。重複・NULL・参照先のない行がある場合は、期待した件数で拒否され、制約は作られなかった。件数を数えない場合と、子の表を読む権限のない役割で観測した場合は`existing-data-unobserved`になった。
- 既存の主キーの置き換え（`primary_key_replace_realdb_test.go`）: 名前が既定でない主キー(a)を(a,b)へ置き換えると、観測した名前で落として付け直され、差分が空になった（新しい主キーは`t_pkey`）。新しいキーの重複とNULLは件数つきで拒否され、旧主キーが残った。参照する外部キーは名前つきで拒否された。観測なしは`unresolved`。観測の後に制約名が変わると古い文は実行できず、再観測で名前が変わる。失敗した文の後も旧主キーが残った。
- 主キーの削除（`primary_key_replace_realdb_test.go`）: 名前が既定でない主キー(a)をなくすと、観測した名前で`DROP CONSTRAINT`され、差分が空になった。参照する外部キーがある場合は名前つきで拒否され、旧主キーが残った。

- 名前だけが違う制約（`constraint_rename_realdb_test.go`）: 宣言した名前が観測と違う一意制約・外部キーが改名され、差分が空になり、一意制約の索引名も変わり、主キーは`child_pkey`のままだった。生成した名前と観測した名前の違いは差分にならなかった。新しい名前が主キーの索引や同じ表の別の制約と同じ場合は`constraint-rename-name-taken`で拒否され、外部キーは表の名前と同じでも許された。観測なしは`unresolved`。観測の後に別の道具が改名した計画は`constraint-rename-source-missing`で拒否され、古い文は実行できなかった。

確認した版は PostgreSQL 16.14（`postgres:16-alpine`）と、名前の生成と既存の表への追加の確認では PostgreSQL 16.15（`postgres:16`）です。他の版・他の提供元は未確認です。

## 未決に対する判断（この参照の範囲）

- **主キーをなくす変更**: 実装した。観測した制約名で`DROP CONSTRAINT`し、参照する外部キーがあれば名前を示して拒否する。`CASCADE`は使わない
- **参照する外部キーの作り直し**: 採用しない。子の表の検査・ロック・再作成を行わず、fail-closedのままにする
- **`CONCURRENTLY`**: この参照では採用しない。トランザクション外のDDL、中断時の無効な索引の後始末、適用直前の再観測との整合を扱っていない。必要になった時点で別に設計する
- **列名の変更**: 推測しない。drop-column+add-columnとして扱い、データ移行の宣言が別に必要
- **パーティション表・PostgreSQL 16以外・他の提供元**: 未確認
- **正式採用**: 仮決めのままで、Ownerの判断を待つ
