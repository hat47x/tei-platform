# Xeadの三視点の対応関係を調べる

この参照実装は、Xeadの設計資料に記述された業務、機能、データの対応関係を読み取り専用で調べます。課題 [#1031](https://github.com/hat47x/tei-platform/issues/1031) に対応します。

利用者が指定したXML形式の設計資料と、読み取り方を定める契約ファイルから、資料に明記された関係と複数の記述をたどって得られた関係を区別します。公開APIの `BuildCrossViewProjection` も同じ入力を直接受け取り、`InspectWithContract` による資料の種類、ルート要素、形式の版の照合を必ず経由します。呼び出し元で組み立てた検査結果を渡して照合を省くことはできません。

通常の出力は件数などの集計結果に限ります。設計資料の本文、旧識別子の値、個別の関係をたどるための識別情報は公開しません。 集計を公開する前に、解析結果の照合値、関係の種類、操作指定、未解決理由を検査します。未知の名称をそのまま集計の項目名にすることはありません。照合値は内容の変化を検知するためのもので、資料の出所や意味上の正しさを証明する署名ではありません。

```bash
go run ./tools/reference-xead-cross-view \
  -input /path/to/local-model.xead \
  -contract reference/xead-source-transcription-contract.synthetic.json
```

上記の契約ファイルは**合成試験用の不完全な例**です。外部の参照モデル全体について、記述要素の網羅性や意味の正しさを保証しません。実際の資料を照合する際は、対象の形式・版・要素に合う契約を別途確認してください。参照モデルの原本や詳細な解析結果は公開リポジトリへ保存しません。

個別の対応関係を手元で調べる場合に限り、次の指定を追加します。この出力は非公開の調査資料として扱ってください。

```bash
go run ./tools/reference-xead-cross-view \
  -input /path/to/local-model.xead \
  -contract reference/xead-source-transcription-contract.synthetic.json \
  -local-projection
```

## 結果の読み方

- 表の利用宣言に有効な作成・参照・更新・削除操作が一つもない場合、操作関係を作らず、`iotable-operation-missing`として未解決に残します。表の記述自体は集計対象です。
- 未知の操作指定があれば、理解できた操作だけを取り出すことはせず、`iotable-operation-marker-unsupported`として未解決に残します。
- 機能から表への操作宣言は、その機能全体での利用候補です。特定の業務作業による更新、実行時の副作用、取引の確定、認可を証明するものではありません。
- 公開用集計では、業務作業から機能を使う記述と、その機能が表を利用する記述を照合し、導出された各経路に必要な根拠がそろっているか確かめます。根拠が欠けた経路や同じ経路を水増しした結果は拒否します。
- さらに、業務作業・機能とのやり取り・表利用宣言の件数が、明示された関係と未解決の記録を合わせた件数に一致するか確かめます。途中で解釈できなかった記述も消さずに数え、矛盾する集計は公開しません。


- 機能とのやり取りの入出力先を、元の機能利用宣言と照合します。`IOID` の前後の空白を除いた値が `0` なら、入出力先を持たない宣言として数えます。同じ利用宣言に複数の解決結果を付けたり、異なる機能の結果を流用したりした集計は拒否します。

## 元資料と公開用集計の照合

`CrossViewPublicAccounting`は、渡された解析結果の項目・件数・関係の**内部整合性**を検査します。機能を解決できた入出力先については、その宣言との対応と「入出力先なし」の件数も確かめます。ただし、作業のない業務手順の総数や、機能の参照を解決できなかった宣言の元の入出力先は、解析結果だけから完全には復元できません。

`CrossViewSourceReconciledAccounting`は、呼び出し元が保持する**元XMLのバイト列と版指定済みの読み取り契約**から、読み取りと三視点の解析を改めて実行します。その結果と提示された解析結果がすべて一致した場合だけ、再解析した結果から公開可能な集計を返します。資料や契約が古い場合、あるいは集計件数だけを変更して照合値を再計算した場合は拒否します。原資料の本文や個別の旧識別子を、この関数の戻り値として公開しません。

この追加の確認は、**呼び出し元から渡された資料が、提示された解析結果の生成元として整合していること**に限られます。資料が本当に元のシステムから得られたか、読み取り契約がすべての要素を正しく解釈したか、旧システムとTEIの意味や動作が同等か、誰がその意味を承認したかは保証しません。外部の非公開資料は安全な作業環境内にとどめ、集計だけを公開します。

集計結果は設計資料を読み取った証拠であり、TEIの正本への受理や、元のX-TEA Driverで実行した結果を意味しません。実機での動作確認は別課題 [#940](https://github.com/hat47x/tei-platform/issues/940) が担当します。


## 事前に確認した集計値との再照合

非公開の参照モデル全体で件数を検証する場合は、元XMLを公開せず、まず手元で集計を出力し、別途取得した観測値と照合したうえで、公開可能な記録だけを保管します。

```bash
# 非公開の資料と、その版に適合する読み取り契約を指定する
go run ./tools/reference-xead-cross-view \
  -input /private/model.xead \
  -contract /private/transcription-contract.json > /private/observed-accounting.json

# 後日、同じ資料・同じ契約から再計算した結果を照合する
go run ./tools/reference-xead-cross-view \
  -input /private/model.xead \
  -contract /private/transcription-contract.json \
  -expect-accounting /private/observed-accounting.json > /private/verified-accounting.json

# 個別の出典情報を保持する解析結果の照合と組み合わせることもできる
go run ./tools/reference-xead-cross-view \
  -input /private/model.xead \
  -contract /private/transcription-contract.json \
  -verify-projection /private/saved-local-projection.json \
  -expect-accounting /private/observed-accounting.json
```

`-expect-accounting`は、**事前に保存した公開用JSONの全項目**を、資料から新たに求めた結果と比較します。業務手順・機能利用・表利用の件数だけでなく、元資料の指紋、読み取り契約、導出規則の版・指紋、未解決件数、根拠上の限界も一致する必要があります。項目の追加、重複したJSON項目、形式不正、旧集計へのすり替え、資料や契約の変更があれば失敗します。エラーの本文には旧識別子や元資料を含めません。

**注意**：最初の集計結果をそのまま基準値にしただけでは、独立した検証にはなりません。元システムの設計者による確認や、別方式で観測した148件・407件・392件などの実測値との突合は、基準値の**採用前**に別途行います。数値の意味や対象版が違う場合は自動的に一致扱いしません。また、この方式で照合できても元資料の真正性、業務意味、旧システムの実行結果、人の承認権限までは確定しません。資料の指紋や集計結果自体の公開可否も利用者が確認し、非公開資料は作業環境内で保持してください。
