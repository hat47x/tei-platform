# ISSUE-000004: 既存ADRを`plan/adr`へ段階的に移行する

- 状態: 提案中

## 背景

ADR-0016で、今後の上位・横断的なADRは`plan/adr/`へ置く方針を採用します。

一方、mainではADR-0001〜0015が`docs/adr/`にあり、README、Architecture、Status、Conformanceなどから多数参照されています。これらを単純に一括移動すると、既存リンクや過去の文脈を壊す可能性があります。

また、移行期間中に同じADR番号を別の意味で再利用すると、設計判断の履歴そのものが曖昧になります。そのため、既存番号は一切振り直さず、新しい`plan/adr/`のADRも0016以降から連番を継続します。

## 関連するProduct Requirement

- RQ-021 Reference / Conformance
- RQ-022 実装済み範囲と設計上の主張の区別

## 作業内容

- `docs/adr/0001`〜`0015`の参照元を確認する
- 既存ADR番号を維持する
- `plan/adr/`へ移す際の互換導線を決める
- README、Architecture、Status、Conformanceからのリンクを一貫して更新する
- `docs/adr/README.md`を互換入口として残すか、移行完了後に役割を終えるかを決める
- 移行後もGit historyから元の文脈を追えることを確認する
- 新旧の保存場所に同じ番号の異なる判断が存在しないことを検査する

## 制約

- ADR番号を振り直さない
- 既存ADRの意味を、移行作業のついでに変更しない
- リンクが壊れた状態を中間成果としてmainへ入れない
- `docs/adr/`と`plan/adr/`を恒久的な二重正本にしない
- 新しいADR番号を既存履歴と衝突させない

## 完了条件

ADR-0001以降を一つの連続した判断履歴として追跡でき、現在の正規保存場所が`plan/adr/`であることをRepository全体から一貫して確認できること。
