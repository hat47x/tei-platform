# 業務データ取込みと初期データの設計

- 状態: 設計案（評価待ち）。実装はしていない。
- 対象Issue: [#1807](https://github.com/hat47x/tei-platform/issues/1807)（親: [#1802](https://github.com/hat47x/tei-platform/issues/1802)）
- 関連する設計: [型付きの業務データ例とScenarioの参照](../../tools/reference-scenario-state-diff/README.md)（[#1131](https://github.com/hat47x/tei-platform/issues/1131)）、[意味の変更に伴う既存データの移行設計](SEMANTIC_CHANGE_DATA_EVOLUTION_DESIGN_2026-10.md)、[機能の業務結果と実行エラーの分離](CAPABILITY_OUTCOME_V1_DESIGN.md)、[副作用を伴う実行の段階](BUSINESS_EFFECT_LIFECYCLE_DESIGN_2026-10.md)

## 1. この文書の役割

人が表計算などで用意した業務データを取り込む仕事と、システムの稼働に必要な初期データを投入する仕事を、TEIの検証と権限の境界を迂回せずに行うための案をまとめます。

旧い設計ツールには、タブ区切りのデータを取り込んで挿入・更新する機能と、初期の記録（ログイン可否の区分、管理者・一般などの区分）を挿入する機能がありました。取込みの結果は、挿入と更新の件数として示され、一意制約の重複や主キーの欠落は誤りとして報告されました。この仕事は実務で頻繁に必要になる一方で、業務の検証、認可、取消を飛ばす近道になりやすい性質があります。

## 2. 避けたい事態

- 取込みが、通常の画面や機能と別の書込み経路になり、Validationと認可を通らない。
- 一部の行だけが成功し、何が入ったのか説明できない。
- 同じファイルを二度取り込むと、二重に登録される。
- 初期データが、意味の正本（受理した定義）と、運用中に変わるデータとで区別されない。
- 取込みの成功を、取り込んだ内容の業務上の正しさの証拠として扱う。
- 取込み元の値（個人情報を含み得る）が、結果の報告や記録に残る。

## 3. 現在の実装で確認できたこと（2026年10月18日の`main`）

| 箇所 | 内容 |
| --- | --- |
| `internal/driver/invocation.go` | Capabilityの実行は、Bindingを解決してAdapterを通して行う。業務上の拒否は業務結果として返り、実行を完了できなかった状態は実行エラーとして分かれる |
| `internal/semantic`のCapability | 入力、出力、業務上の結末、データへの効果（作成・更新）を宣言する。効果は意図の宣言で、実際の保存の証拠ではない |
| `tools/reference-scenario-state-diff` | 型付きDatasetとSnapshotを、モデルに照らして検査する（型の不一致、未知の項目、キーの欠落・重複、参照先の欠落）。実Driverでの実行は含まない |
| 削除 | 現在のモデルでは削除の効果を表現できない |

つまり、**データの形を検査する部品**（#1131の参照）と、**書込みを検証と認可つきで行う経路**（Capabilityの実行）は別々にあり、取込みはその二つを結ぶ仕事です。

## 4. 案

### 4.1 取込みを専用の書込み経路にしない

取込みの各行は、通常のCapability（作成・更新）の実行として扱います。これにより、Validation、認可、業務結果と実行エラーの分離、観測が、画面からの操作と同じになります。取込み専用の書込み処理は作りません。

取込みという操作自体も、権限を持つ主体だけが実行できるCapabilityとして宣言します。誰が取り込めるかは、業務の定義の一部です。

### 4.2 段階

| 段階 | 内容 | 書込み |
| --- | --- | --- |
| D0 | 形の検査。見出しの重複、未知の項目、型の不一致、キーの欠落・重複、参照先の欠落を、モデルに照らして検査する（#1131の部品を再利用する） | なし |
| D1 | 行ごとの予行。各行をCapabilityの検証まで評価し、業務上の結果（受け付ける、拒否する、理由）を一覧する。保存はしない | なし |
| D2 | 実行。D1で受け付けられた行だけを、明示した確認の後に実行する。行ごとの結果を記録する | あり |
| D3 | 再実行。同じ取込みを再度行っても、二重に登録されない（4.4） | あり |
| D4 | 初期データの区分（4.5）を、受理した定義と結び付ける | 定義の側 |

D0とD1は書込みを伴わないため、先に作れます。D2からが、副作用を伴う実行です。

### 4.3 行ごとの結果と、全体の扱い

- 結果は行ごとに「受け付けた」「業務上の理由で拒否した」「実行できなかった」に分けます。業務上の拒否と、実行を完了できなかった状態を混ぜません。
- 全体を一つの取引にするか、行ごとに確定するかは、取込みの宣言で選びます。既定は行ごとの確定で、途中までの結果を必ず説明できる形にします。全体を一つの取引にする場合は、一つでも拒否があれば何も保存しません。
- 記録に取込み元の値を残しません。残すのは、行番号、結果の種別、理由の符号、件数です（開示の規則は[CLI C2の開示境界](CLI_C2_DISCLOSURE_BOUNDARY_DESIGN.md)に合わせる）。

### 4.4 再実行と二重登録の防止

取込みの単位に識別子を付けます。識別子は、取込み元の内容（ダイジェスト）と、対象のCapability・版から決定的に作ります。同じ識別子の実行が既に確定している行は、再実行で重ねて作成しません。更新は、基準の版を要求し、取込み後に行が他で変更されていた場合は、黙って上書きせず競合として扱います。

### 4.5 初期データの区分

| 区分 | 例 | 置き場所 |
| --- | --- | --- |
| 定義に属する参照データ | 区分値の一覧、役割の一覧など、システムの意味に含まれるもの | 受理した意味の正本。取込みではなく定義として受理する |
| 稼働に必要な初期の運用データ | 最初の管理者など | 取込み（D2）で投入する。権限の付与は取込みの結果としない |
| 運用中に変わるデータ | 顧客、受注など | 取込み（D2）または通常の機能 |

最初の管理者のように、権限に関わる初期データは、特に慎重に扱います。取込みで管理者を作る権限を、取込みを実行できる主体に暗黙に与えません。

## 5. 効果仮説と観測（#1973）

- 従来の限界: 型付きの例の検査（#1131）と、Capabilityの実行は別々にあり、取込みを検証と認可つきで行う経路がない。
- 効果: 取込みが通常の機能と同じ検証・認可・結果の分離を通る。予行（D1）で、保存せずに拒否の理由を確かめられる。再実行で二重登録が起きない。
- 観測: 同じ入力で、D1の予行の結果とD2の実行の結果が一致する。画面の機能で同じ値を入力した場合と、結果が一致する。
- 撤回条件: 取込みの各行を通常のCapabilityとして実行すると、件数が多い場合に実用にならないと分かった場合は、一括実行の別経路を、同じ検証と認可を通る条件つきで再設計する。
- 未確認: 実データベースでの実行、大きな件数での性能、全体を一つの取引にする場合のロックの影響。

## 6. 受入シナリオと否定試験

| 番号 | 状況 | 期待する動作 |
| --- | --- | --- |
| DI-01 | 見出しに重複した項目名がある | D0で止める。保存しない |
| DI-02 | 型が合わない値、未知の項目 | D0で行番号と理由の符号を示す。値を報告に載せない |
| DI-03 | 主キーの値が欠けている行 | D0で拒否する |
| DI-04 | 業務のValidationに反する行 | D1で拒否の理由を示す。保存しない |
| DI-05 | 認可されていない主体が取り込む | 実行前に拒否する。取込みの存在を示す情報を出し過ぎない |
| DI-06 | 一部の行だけが拒否される（行ごとの確定） | 受け付けた行だけが保存され、拒否した行の一覧と理由が残る |
| DI-07 | 全体を一つの取引にした場合に一行が拒否される | 何も保存されない |
| DI-08 | 同じファイルを二度取り込む | 二度目は重ねて作成しない |
| DI-09 | 取込み後に、更新対象の行が他で変更された | 競合として扱い、上書きしない |
| DI-10 | 実行の途中でProviderが応答しない | 実行を完了できなかった行を、業務上の拒否と区別して示す。未確定の行は成功としない |
| DI-11 | 初期データで管理者を作る | 権限の付与は取込みの結果にならない。権限は別の受理を経る |

## 7. 結論を出していない範囲

- 取込み元の書式（タブ区切り以外）と、文字コードや改行の扱い。
- 取込みの識別子の具体的な作り方と、保存場所。
- 全体を一つの取引にする場合の件数や時間の上限。
- 削除を伴う取込み。現在のモデルは削除の効果を表現できないため、対象外とする。
- 個人情報を含む取込み元の保管と廃棄。公開範囲と合わせて別に判断する。
- 多言語の業務データを含む取込み（[多言語の業務データの設計](MULTILINGUAL_BUSINESS_DATA_AND_AI_TRANSLATION_2026-10.md)との整合）。
