# 設計の補助情報の置き場所

- 状態: 設計案。採用前であり、実装も済んでいない。
- 対象Issue: [#1808](https://github.com/hat47x/tei-platform/issues/1808)（親: [#1802](https://github.com/hat47x/tei-platform/issues/1802)）
- 関係する文書: [設計ツールの機能移植対応表](AUTHORING_TOOL_FEATURE_TRANSFER_MAP_2026-10.md)

## 1. この文書の役割

設計の本体（Data、関係、機能、業務手順）に付随する情報を、どこに置くかを決める案です。対象は、用語と規則、改訂履歴、注記、しおり、区分（主題領域、種別、課）、要素の記述文、図の配置です。

旧い設計ツールでは、これらが同じファイルの中に、同じ重みで並んでいました。記述欄の中の特定の文字列で注記を表す例もありました。TEIでは、どれが意味の正本で、どれが導出でき、どれが運用上の記録かを分けないと、意味の版が補助情報の変更で動いたり、逆に受理されていない文章が意味として読まれたりします。

## 2. 判定の問い

補助情報は、次の問いに上から順に答え、最初に当てはまる置き場所へ置きます。

| 順 | 問い | 当てはまる場合の置き場所 |
| --- | --- | --- |
| 1 | 変えると、実行、検証、認可、Targetへの変換の結果が変わるか | 意味の正本。受理を経る |
| 2 | 意味の正本や版管理から再計算できるか | 導出。保存しない |
| 3 | 閲覧する人ごとの好みか | 利用者ごとの局所の状態。Sourceへ置かない |
| 4 | 図や画面の見せ方だけに関わるか | 表示情報。意味の版を動かさない |
| 5 | 上のいずれでもなく、人や生成AIが書いた作業上の記録か | 運用の記録。対象の意味参照を持つが、意味の版に含めない |

2が1より前に来ないことが重要です。再計算できる情報でも、変えると実行が変わるなら、それは意味の一部です。

## 3. 項目ごとの案

| 項目 | 旧ツールでの形 | 案 | 理由と条件 |
| --- | --- | --- | --- |
| 要素の名称 | 要素の属性 | 意味の正本（既存のSymbol）。表示名は多言語の表示資源 | 既存の境界に従う（[#1551](https://github.com/hat47x/tei-platform/issues/1551)） |
| 要素の記述文 | 記述欄の自由文 | 運用の記録を既定とし、実行に効く文は意味の正本の宣言へ分ける | 自由文を意味として読まない。AIが記述文から規則を補完しない |
| 用語の名称の索引 | 用語集の見出し | 導出 | 名称と表示資源から作る |
| 用語の意味の定義 | 用語集の本文 | 意味の正本の候補（受理済みのときだけ） | 受理されるまでは運用の記録。定義の根拠を持たない用語はunresolved |
| 規則の文章 | 用語と規則 | 実行に効く規則は検証規則などの宣言へ。それ以外は運用の記録 | 文章と宣言の対応を、レビューで確認できること |
| 注記 | 記述欄内の印（`@NOTE@`）と一覧 | 運用の記録。対象の意味参照、種別（課題、質問、メモ）、状態、記入者を構造化して持つ | 文字列の約束に依存しない。意味の版に含めない |
| 改訂履歴（事実） | 改訂の表 | 導出（版管理と受理の記録から） | 人が転記しない。二重の正本を作らない |
| 改訂履歴（理由） | 改訂の表の説明 | 受理の記録に付く運用の記録 | 受理の主体と版に結び付ける（[#267](https://github.com/hat47x/tei-platform/issues/267)） |
| しおり | しおり一覧 | 利用者ごとの局所の状態 | Sourceへ置かない。共有したい場合は注記へ |
| 主題領域 | 区分、図のまとまり | 表示情報を既定とする。所有境界として使う場合のみ意味の正本 | 所有（サブシステム）との混同を避ける（[#1132](https://github.com/hat47x/tei-platform/issues/1132)） |
| 表の種別 | 区分 | 意味の正本の分類（拡張の宣言）または導出。要確認 | 実行に効かない分類なら導出または運用の記録 |
| 作業の種別 | 区分 | 業務手順の宣言の一部として扱う（[#1125](https://github.com/hat47x/tei-platform/issues/1125)） | |
| 機能の種別 | 区分 | 標準部品の選択として既存の機構へ。重複して持たない | 核へ列挙を複製しない |
| 課（部署） | 区分 | 業務上の担当者の分類として業務手順の宣言へ。認可のRoleと混同しない | #1125の境界 |
| 図・スライドの配置 | 座標、順序 | 表示情報 | 意味の版を動かさない |

「要確認」は、旧ツールの定義だけでは実行に効くかを判定できない項目です。着手時に原ソースの処理を読み直して確定します。

## 4. 不変条件

- 表示情報、運用の記録、利用者ごとの状態を変更しても、意味の版（digest）は変わらない。
- 運用の記録は、対象を意味参照で指す。対象が削除・分割された場合は、参照切れとして診断に残す。黙って付け替えない。
- 受理されていない文章は、意味として扱わない。生成AIの補完で、定義の根拠のない用語に意味を与えない。
- 導出できる情報（改訂の事実など）を、人が重複して書く欄を作らない。
- 記述欄の中の文字列に、構造上の意味（注記の印など）を持たせない。

## 5. 移行の扱い

旧い設計の取込み（[#1805](https://github.com/hat47x/tei-platform/issues/1805)）では、補助情報を次のように扱います。

- 記述欄の印で表された注記は、構造化した注記の候補へ変換する。印の意味が確認できない場合は、運用の記録として原文のまま保持し、unresolvedとする。
- 改訂の表は、事実と理由を分け、事実が版管理から導出できる場合は転記しない。
- 区分は、実行に効く根拠が確認できるものだけを意味の正本の候補にし、残りは表示情報か運用の記録にする。

## 6. 未決の事項

- 運用の記録を保存する場所（Source内の別ファイル、または別の記録庫）と、公開時の扱い。
- 用語の意味の定義を表す拡張の形。名称と定義を分ける最小の宣言。
- 注記の状態（未対応、対応済み）の変更を、受理の対象にするか。
- 表の種別が、標準部品や生成に影響する場合の扱い。

## 7. #1808の受入条件との対応

| 受入条件 | 本文書での扱い |
| --- | --- |
| 各補助情報の置き場所が、理由とともに決まっている | 3章の表（要確認の項目を除く） |
| 記述欄の印に依存せずに、注記を一覧できる | 3章の注記、5章 |
| 版管理から導出できる履歴を、人が重複して書かない | 3章の改訂履歴、4章 |
| 表示情報の変更が、意味の版を変えない | 4章の最初の条件 |
| 用語の意味の定義が、AIの推測で補完されない | 3章の用語、4章 |
