- 状態: **棚卸しのみ**。強制を実装したものではありません。
- 目的: 権限の強制点をどこに置くかを決めるため、ファイル・ネットワーク・環境変数に触る箇所を数える。

## 2. 分かったこと

1. **実行の中核（`internal/driver`・`internal/execution`・`internal/plugin/runtime`・`internal/servicehost`）が直接触るファイル操作は1件だけ**（`internal/plugin/runtime/process_pinned_linux.go` の一時ファイル作成）。中核は意味と契約を扱い、外部へのアクセスは**アダプタと参照ツール**が持っています。
2. したがって、権限の強制を能力の呼出し直前（`execution.Invoke`）に置いても、**実際のアクセスは素通り**します。アクセスを持つのは `tools` 側のアダプタであり、そこを強制点にしない限り「宣言と実際」はつながりません。
3. `os.Getenv` は 31 件あり、秘密の取得が宣言（`secret`）を通っているかは別に確かめる必要があります。

## 3. 強制点の候補

| 候補 | 利点 | 欠点 |
| --- | --- | --- |
| アダプタ境界（`tools` の各アダプタ） | 実際のアクセスに最も近い | アダプタごとに実装が必要。数が多い |
| 中核の共通アダプタ層（新設） | 一箇所で済む | 既存アダプタの移行が必要。ツールが中核を通らない経路が残る |
| OS のサンドボックス（権限を落として起動） | 宣言と独立に守れる | 実行環境の対応が必要。TEI の外側の仕組み |

**推奨（仮説）**: まず「中核の共通アダプタ層」を一箇所作り、そこを通るアダプタだけを対象にする。通らない経路は**通らないと記録**し、対象を広げる。OS のサンドボックスは別途、実行環境の担当として切り分ける。

## 5. 追記（2026-11-06）: 判定と記録の最小実装

`internal/access` に、判定と記録を一箇所にした最小の実装を追加しました。

```go
guard := access.Guard{Granted: grants, Journal: access.File{Path: "access.jsonl"}}
decision, err := guard.Check("sales.close", requirements)
```

- 判定は `permission.Missing`（付与が要求を覆うか）を使う。
- **すべての判定を記録**する（許可も拒否も）。記録できない場合はエラー（記録できない判定を黙って通さない）。
- 記録は JSON Lines。壊れた行はエラーとして報告し、その行より前は返す。

**まだ強制ではありません**。アダプタ（`tools`）がこの `Guard` を通るようになるまで、実際のアクセスは止まりません。通るアダプタを一つずつ増やし、**通らないものは通らないと記録**する方針です。
## 6. 追記（2026-11-06）: ファイル操作の強制（アダプタ1つ分）

`internal/access.FileSystem` を追加しました。**能力に代わって**ファイルを読み書きするアダプタで、アクセスの直前に判定と記録を行います。

- `Root` の外を指すパスは、権限が許していても**拒否**する（`../escape.txt` など）。
- 権限が覆っていないアクセスは**拒否**し、**ファイルを残さない**（拒否が副作用を残さない）。
- アクセスは記録される（読みも書きも）。
- `Root` が空なら何も許さない。

**まだ一部分です**。`tools` の既存アダプタは `os` を直接呼んでおり、この `FileSystem` を通っていません。通すアダプタを一つずつ増やす必要があります。

**Windows の区切り文字**: スコープの包含判定が `/` だけを見ていたため、バックスラッシュで解決されるパスが覆われない不具合を試験で発見し、両方の区切り文字を受け入れるよう修正しました。
## 7. 追記（2026-11-06）: ネットワーク操作の強制

`internal/access.Network` を追加しました。接続の直前に判定と記録を行います。

- 接続先が付与で覆われていなければ**拒否**し、**ソケットを開かない**。
- `Dialer` を差し替えられるので、**ソケットを開かずに**判定を試験できる。
- 接続の判断も記録する（許可・拒否とも）。記録に失敗した場合はエラー。

これで、ファイルとネットワークの両方に「宣言 → 判定 → 実際の操作」の形ができました。**既存のアダプタはまだ通っていません**（`tools` の実装は `os`・`net` を直接呼んでいます）。
## 8. 追記（2026-11-06）: 秘密の読み取りの強制

`internal/access.Secrets` を追加しました。秘密を読む直前に判定と記録を行います。

- 名前が付与で覆われていなければ**拒否**し、**読まない**。
- `SecretReader` を差し替えられるので、秘密の保管場所無しで判定を試験できる。

これで三種（ファイル・ネットワーク・秘密）すべてに「宣言 → 判定 → 実際の操作」の形ができました。**既存のアダプタはまだ通っていません**。

## 10. 追記（2026-11-07）: 拒否を残す

第6章の `FileSystem` は `Root` の外を指すパスを**権限を見る前に**拒否します。その拒否は `Guard.Check` を通らないため、**記録されていませんでした**。記録が無い拒否は「起きなかったアクセス」と区別できず、**Root の外へ出ようとした試行**だけが痕跡を残さない状態でした。

`FileSystem.resolve` で、`inside` が失敗したときも判定を1行記録するようにしました。

- 記録は `Guard` が書くのと同じ形（`Capability`・`Allowed=false`・`Missing`）です。読む側は、権限不足による拒否と Root 外の拒否を**同じ形**で扱えます。
- `Missing` には要求と理由（`outside the root: …`）が入ります。
- **ジャーナルが壊れていても、返すエラーは変えません**。パスはすでに拒否されており、そこでジャーナル失敗を返すと「記録できなかった」を「拒否した」より優先して報告してしまいます。記録の失敗は握りつぶしていますが、拒否そのものは呼び出し側に伝わります。

**この追記が示さないこと**: 記録の失敗を呼び出し側が知れること（**知れません**。拒否を優先する設計判断です）。記録が改竄されないこと（`access.File` は追記のみ）。
## 11. 訂正（2026-11-07）: 閉じ込めは文字列の比較ではなかった

第6章は「`Root` の外を指すパスは拒否する」と書いていましたが、**判定は文字列の比較**でした。`Root` の中に**外を指すリンク**を置けば、書かれたパスは内側に見えたまま、実際の書き込みは外へ出ます。実機で再現して確認しました。

```text
root/escape -> C:\...\outside     （ジャンクション）
root/escape/secret.txt            ← 文字列では内側、実際は外
```

`os.OpenRoot`（Go 1.24 以降）に置き換え、**閉じ込めを OS に委ねました**。

- `os.Root` は `openat` 系の操作で、リンク・ジャンクション・`..` を通じた脱出を**OS の側で**拒否します。
- 文字列の比較をやめたのは、**「解決してから、その名前で開く」までの隙間**にリンクを作られると比較が通ってしまうためです。判定と実行が同じ操作になれば、その隙間がありません。
- 文字列側の検査は残しています（絶対パスと `..` の早期拒否）。安価で意図が読める形で拒否できますが、**最終的な根拠は OS の拒否**です。
- OS が拒否した場合も**記録**します。記録は「権限が無い」ではなく「Root が拒否した」と書き、**何が起きたか**を残します。

### `os.Root` の実際の挙動（想定と違った）

`os.Root` は**リンクを一律に拒否**します。内側を指すリンクでも `path escapes from parent` になります。当初「内側なら通る」と想定して試験を作りましたが、**CI の Linux で落ちて**実際の挙動が分かりました（Windows でも同じ）。

穴ではなく**厳しすぎる**ので、期待値を実測に合わせ、その挙動を試験として書き留めました（`TestFileSystemRefusesALinkThatStaysInsideDocumentsTheLimit`）。将来の Go が内側リンクを通すようになれば、この試験が落ちて変更が見えます。

**この訂正が示さないこと**: プロセスの隔離。これは**パスの閉じ込め**であり、能力が別の経路でアクセスを得る場合（自分でソケットを開く、別の API を使う）は止めません。
