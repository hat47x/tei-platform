# データ導出の評価文脈と決定的再評価（#1720 D12）

状態: 採用前の設計整理。意味契約の正本は[データ導出規則の最小意味契約](DATA_DERIVATION_REFERENCE_CONTRACT.md)に置き、本書は文脈依存の扱いだけを定める。実装状況を示すものではない。

## 問題

属性列以外に依存する導出（経過日数、タイムゾーン毎の営業日、適用中tax区分など）が、隠れた `time.Now()`、マシン既定Locale、Process Environment、Session値へ依存すると、同じ受理済み規則と同じ行でもGo／SQL／Webで結果が変わる。これは D3 のキャッシュ再利用と D7 の根拠追跡も壊す。

## 入力の三区分

- 業務入力: 規則の意味に属する値（数量、単価）。
- 評価引数: 結果へ影響する必要最小限の文脈値（as-of日時、営業日暦、Locale）。
- 信頼済みContext: principal、tenant、権限などHostだけが供給する値。

ユーザーが渡した `tenant` や `clock` 文字列を認可や評価の根拠にしない。影響しない環境値まで全規則へ宣言を強制しない。必要な文脈が無いときは Host 環境の既定値へ黙って落とさない。

## 決定的再評価の条件

同じ Rule ID・Rule revision・typed inputs・必要文脈・実装の意味契約を固定した再評価が同一の意味結果になること。文脈へ含めるのは結果へ影響する必要最小限の値だけとする。

- 時刻依存演算子は評価開始時に確定した基準時刻から計算し、一行ごとの隠れた時計参照を禁止する。
- 基準時刻はHostが供給し（#1118）、未供給時は fail-closed とする。OS時刻へ fallback しない。
- タイムゾーン、営業日暦、Locale／照合順序が結果へ影響する場合、型・版・出所を明示する。表示時の言語切替（#1453/#1551）と業務上の計算値を区別する。
- ネットワーク由来の価格・暦・レートは、事前取得した型付き入力として供給するか既存Query/Capabilityを明示して実行し、純粋な規則本文へ隠れたI/Oを混ぜない。

## 段階

- M2: 既存 #1118 のHost-supplied contextを参照する小さなReferenceと試験（`elapsed-days` など）。実装は `reference/derivation-context/`。
- M3: 案件で必要ならSQL/Goの同等性と #1641 の再利用条件へ接続する。

## 非目標
