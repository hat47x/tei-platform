# データ導出規則の最小意味契約（検証案）

対象：#1637。問い合わせ適用は #1640、鮮度と確定値は #1641、更新・副作用は #1129 に委譲する。本書は採用前の設計案であり、製品機能の実装完了を意味しない。

## 分離する二つの対象

- **規則定義**：何を入力とし、どの型の結果をどう求めるか。規則ID、型付き入力参照、演算子と版、結果型、依存規則、純粋性を持つ。入力参照は物理列名ではなく意味上のIDを使う。
- **適用の結び付け**：規則IDを、意味属性、問い合わせ固有の結果、集合計算などの対象IDへ適用する。対象IDは規則IDと別に扱う。同名の列や属性を自動結合しない。

同じ規則を複数の対象へ適用できるが、対象の認可・NULL・評価文脈が同一だと推測しない。規則は保存値を暗黙に更新しない。既存の `semantic.Attribute`、`Relation`、#988 の演算子、#1120 の安定参照を利用し、新しいCanonical型や式言語を先に固定しない。

## 型付きの確認

`internal/semantic/derivationref` の参照実装は、規則の任意の型付き契約（`InputTypes`・`OutputType`）と、適用先の`TargetType`を検査する。型の不一致は`ErrType`、未対応の演算子は`ErrOperator`として区別し、名前や位置の一致で型を推測しない。

- 規則の型付き契約が揃っているとき、`multiply`は数値型（`decimal`・`integer`）の2入力と数値の結果型を要求する
- 適用先の`TargetType`が規則の`OutputType`と異なる場合は拒否する
- 一つの規則を複数の適用先へ結び付けられる。適用先を変えても規則は変わらない
- `InputTypes`・`OutputType`・`TargetType`は任意であり、指定しない既存の呼出しは従来どおり動く

これは参照用の宣言であり、Coreの型体系や新しい式言語を固定しない。

## 評価結果と診断の最小区別

| 状態 | 意味 | 期待する処理 |
| --- | --- | --- |
| 値 | 宣言した型に適合する結果 | 正常に返す |
| 正当なNULL | NULL方針により値がNULLとなる | 0に変換しない |
| 入力未取得 | 必要な入力が取得されていない | 参照先0件と区別して診断 |
| 参照先なし | 解決済みの関係に一致する対象がない | 関係の多重度とNULL方針に従う |
| 多重度違反 | 一件を要求した参照先が複数一致 | 任意の先頭行を採用しない |
| 評価不能 | 型、演算子、循環、実行能力などの不整合 | 値として偽装しない |

この表は評価上の区別を示すもので、単一の巨大な公開列挙型を要求しない。認可拒否は既存の実行権限の境界に従い、利用者に診断から秘匿情報を漏らさない。

## 最小受入例

| 入力 | 期待結果 |
| --- | --- |
| 数量2、単価300 | 600 |
| 数量0、単価300 | 0 |
| 数量NULL、NULL伝播を宣言 | NULL |
| 単価を未取得 | 入力未取得 |
| 一件参照に2件一致 | 多重度違反 |
| 規則A→B→A | 循環を拒否 |
| 未解決の演算子 | 評価不能 |
| 純粋な規則が外部書込みを要求 | 拒否 |

数値は浮動小数点の暗黙変換を避け、演算子契約の精度・丸め・通貨単位に従う。計算に使う規則・入力・評価文脈が固定されている場合に限り決定論性を検査する。

## 最小参照実装の進め方

1. 既存の演算子と意味参照で上記の例を表現できるかを確認する。
2. 規則定義と適用先を分離した小さな合成Fixtureと、正常・負例の契約試験を作る。
3. 未解決の能力、循環、NULL、参照多重度を意図的に失敗させる。
4. 結果を #1637 に記録し、#1640 の問い合わせ計画へ渡す。
5. Coreの型追加・DSLの新構文・共通実行器の導入は、既存契約で表現できない具体例が出た時点で判断する。

**非目標**：旧X-TEAのBR/AR実行順の標準化、native SQLの自動書換え、全SQL方言の最適化、キャッシュ、確定値の書換え、外部副作用。
