# 横断検索と一括置換を変更案として扱う（#1804）

ステータス: **設計案（PoC）**。読み取り専用の横断検索と、置換を変更案へ変換する最小経路を定める。正本の変更は受理境界（#267）を経由するまで行わない。#1804 の Issue 本体に従う。

## 1. 目的

旧モデラーはモデル全体を要素種別・属性・文字列で走査し、選択結果を一括で置換できた。識別子と名称を同じ操作で置換できるため、参照を壊す危険があった。TEI には探索（#363、クローズ済み）と変更の影響解析（ISSUE-000034 / #362）があるが、「意味の記述や名称を横断して探し、置換を変更案として扱う」経路が担当されていない。

本設計は、その経路を最小の形で実証する。検索は正本を変更しない読み取りに限定し、置換は対象・置換前後・影響・基準版を持つ変更案へ変換して受理境界へ渡す。

## 2. スコープ

- 意味の要素（名称、記述、規則、表示用の文言）を種別・属性で絞って検索する（読み取り）
- 置換を、対象・置換前後・影響・基準版を持つ変更案へ変換する
- 置換対象を、意味の記述、表示用の文言、スクリプトの本体から選択できる
- 受理境界（#267）へ渡す。受理するまで正本を変更しない

## 3. 効果仮説と観測（#1973）

- 従来の限界: 探索と影響解析はあったが、置換を変更案として扱う経路がなく、識別子と名称を同じ操作で置換すると参照を壊す危険があった。
- 効果: 意味の記述や名称を横断して探せる。置換は変更案として保持され、プレビューに影響が出る。正本は受理まで変更されない。
- 観測: 1 件の参照 Workspace から、種別・属性で絞った検索結果を列挙できる。1 件の置換対象を変更案へ変換し、影響する参照をプレビューできる。受理前は正本の意味が変わらない。
- 撤回条件: 受理境界（#267）の変更案の形式が変わり、より直接の経路ができた場合は、この層を廃止する。
- 未確認: 大規模 Workspace での検索性能、置換対象の選択 UI、スクリプト本体の置換の安全性、受理後の再投影。

## 4. 検索（読み取り）

検索は `IndexedLoadedSnapshot` の Source Index を読み、`semantic-*` の `definition` 役割のトークンを種別・属性で絞る。正本（Workspace の意味）は変更しない。

- 入力: 種別（`semantic-data`, `semantic-attribute`, `semantic-capability` 等）、属性名、文字列パターン
- 出力: 対象の Canonical ID、位置（ファイル・行・列）、一致した文字列
- 副作用: なし。読み取りのみ

## 5. 置換を変更案へ変換する

置換は対象ごとに変更案（change proposal）へ変換する。変更案は #267 の受理境界が受け取る形式に合わせる。

変更案の最小項目:
- 対象: Canonical ID と位置
- 置換前: 旧文字列
- 置換後: 新文字列
- 影響: 参照している他の意味要素の一覧
- 基準版: 受理時の Workspace の版

## 6. 受入条件

- [ ] 検索が正本を変更しない
- [ ] 置換が変更案として保持され、プレビューに影響が出る
- [ ] 受理前は正本の意味が変わらない

## 7. 未確認・境界

- 検索性能（大規模 Workspace）
- 置換対象の選択 UI
- スクリプト本体の置換の安全性
- 受理後の再投影
- 旧ツールの実行規約や画面操作を、TEI の意味の正本へ持ち込まない（#1802 の境界に従う）
