# 権限の現状調査（2026-11）

- 状態: **調査のみ**。権限の強制を実装したものではありません。
- 目的: 「権限設定に関する監査が未完了」という現在地を、リポジトリに実在するものだけから整理する。
- 関連: [全体構成](../../docs/architecture.md)、[実行先の現状調査](HOST_TARGET_SURVEY_2026-11.md)

## 1. 実在するもの

| 対象 | 実在するもの | 何をしているか |
| --- | --- | --- |
| 権限の型 | `internal/permission`（`Spec`） | 種別（`filesystem`・`network`・`secret`）・アクセス（`read`・`write`・`read-write`・`connect`）・`scope` を持つ。`Validate` が組み合わせを検査する |
| 宣言の検証 | `internal/validation`（`INVALID_PLUGIN_PERMISSION`・`DUPLICATE_PLUGIN_PERMISSION` 等） | プラグイン能力が宣言する権限の形式と重複を検査する。環境の `PermissionGrants` も検証対象 |
| 能力の要求 | 検証試験 `TestCapabilityPermissionMustBeExplicitlyGranted` | 能力が要求する権限が明示的に与えられていることを確かめる |

## 2. 効いている範囲

- **宣言の整合**。権限の書き方、重複、能力が要求する権限と付与の対応が検証されます。
- つまり「宣言として矛盾していないか」は確かめられています。

## 3. 効いていない範囲

- **実行時の強制**。`internal/driver`・`internal/execution`・`cmd` から `permission` を参照している箇所はありません（検索して確認）。権限を破る操作を**実行の入口で拒否する仕組みはありません**。
- **プロセスの分離・サンドボックス**。権限が守られることを保証する隔離はありません。
- **監査の記録**。誰がいつ何を要求し、何が起きたかの記録はありません。

## 4. 危険の整理

「権限を宣言している」と「権限が守られている」は別です。現状は前者だけで、後者の根拠はありません。とくに次の二つは、宣言があるために**安全に見えてしまう**危険があります。

1. ファイルシステムへの書き込みを宣言していても、実際の書き込みを止める層が無い。
2. ネットワーク接続を宣言していても、接続を制限する層が無い。

## 5. 次に確かめる順序（提案）

1. **強制の場所を決める** — 能力の呼出し直前（`execution.Invoke`）で宣言を照合し、宣言外のアクセスを拒否する。期間・効果の前提と同じ形にできる。
2. **実際のアクセス経路を数える** — ファイル・ネットワーク・秘密に触る箇所を列挙し、それぞれが強制点を通るか確かめる。
3. **記録する** — 拒否と許可を、実効の記録として残す（期間の状態と同じ「意味の外の記録」）。

## 6. この調査が主張しないこと

- 権限が守られていること。
- 強制の実装方針の決定。
- 既存の宣言が十分であること。
## 7. 追記（2026-11-06）: 付与が要求を覆うかの判定

強制の最初の部品として、**付与が要求を覆うか**を判定する関数を追加しました（`internal/permission/cover.go`）。

- `Covers(grant, requirement)`: 種別が同じで、アクセスが要求を含み（`read-write` は `read`・`write` を含む）、スコープが要求を含む（等しいか、区切り文字の後ろへの前方一致）。`/var/data` は `/var/data/invoices` を覆いますが、`/var/database` は覆いません。
- `Missing(granted, required)`: 覆われていない要求を**すべて**返す（最初の一つで止めない）。

**まだ強制ではありません**。実行の入口から呼ぶ配線と、実際のアクセスを止める仕組みは未着手です。
## 8. 追記（2026-11-06）: 停止条件への接続

`execution.PermissionPreconditions(required, granted)` を追加し、権限の不足を無人実行の停止条件に載せました。

- 能力が要求する権限が付与で覆われていなければ、**その操作の手前で止まる**（理由に不足する権限をすべて列挙）。
- 要求を持たない能力、対応表が無い場合は止めない。
- `CombinePreconditions` で期間・効果の前提と合成できる。

**限界（重要）**: これは**宣言の比較**であり、プロセスの隔離ではありません。能力が別の経路でアクセスを得た場合、この判定では止められません。実際の隔離は未着手です。

**未着手**: 実際のアクセス経路の列挙と、それぞれが強制点を通ることの確認、拒否・許可の記録。
## 9. 訂正（2026-11-06）: サンドボックスは既にあった

第3章で「プロセスの分離・サンドボックスは無い」と書きましたが、**誤りでした**。`internal/plugin/runtime/host_sandbox.go` に、プラグインを実行するホストのサンドボックスがあります。

| 実在するもの | 内容 |
| --- | --- |
| `HostSandboxLauncher.Invoke` | 実行前にポリシーを適用し、適用できない場合は**実行しない**（`deny-by-default` のネットワーク／ファイルシステムで、適用手段が無ければエラー） |
| `SandboxProfile` | `DenyNetworkByDefault`・`DenyFilesystemByDefault`・`NetworkAllowlist`・`Mounts`・`SecretHandles`・`SecretInjections` |
| `SandboxSpec.Permissions` | 要求された `permission.Spec` を**運んでいる** |

**正確な不足は「サンドボックスが無い」ではなく「宣言とサンドボックスが繋がっていない」です。**

- サンドボックスの許可リスト（`NetworkAllowlist`・`Mounts`・`SecretHandles`）は `SandboxProfile` が決めます。
- `SandboxSpec.Permissions` は運ばれますが、**プロファイルがその宣言から導かれたことを確かめる検査はありません**（`spec.Permissions` を読む実装が見当たりません）。
- したがって、宣言より広い許可リストを持つプロファイルでも、そのまま実行できます。

## 10. 次に確かめること（第9章の訂正を踏まえて）

1. `SandboxProfile` が `permission.Spec` から**導出**されるようにする（ネットワーク許可リスト＝`connect` のスコープ、秘密のハンドル＝`secret:read` のスコープ、`deny-by-default` は宣言の有無から決める）。
2. 導出したプロファイルと、渡された `SandboxSpec.Permissions` の**一致**を実行時に確かめる。
3. 導出できない項目（マウントなど）は、**導出しないと記録**する。
## 11. 追記（2026-11-06）: プロファイルの導出

`runtime.ProfileFromPermissions` を追加しました。宣言（`permission.Spec`）からサンドボックスのプロファイルを導きます。

| 宣言 | 導出 | 備考 |
| --- | --- | --- |
| `network` / `connect` | `NetworkAllowlist` にスコープ | 昇順に整列 |
| `secret` / `read` | `SecretHandles` にスコープ | 昇順に整列 |
| `filesystem` | **導出しない** | スコープはホストパスでもアクセス様式でもないため、マウントは作らない（「導出しない」と返す） |
| 秘密の注入 | **導出しない** | 宣言に現れない。明示的に渡す必要がある（「導出しない」と返す） |
| 宣言なし | 両方 `deny-by-default` | 何も許さない |

**導出しないものを、導出しないと返す**のが要点です。マウントや注入を推測で埋めると、宣言に無い許可を作ってしまいます。**プロファイルと宣言の一致を実行時に確かめる配線はまだです。**
## 12. 追記（2026-11-06）: プロファイルが宣言を超えていないかの検査

`runtime.ProfileExceedsDeclarations(profile, perms)` を追加しました。プロファイルが宣言より広い場合に、その理由を列挙します。

| 検査 | 内容 |
| --- | --- |
| 既定 | ネットワーク・ファイルシステムの両方が `deny-by-default` であること |
| ネットワーク | 許可リストの各項目が、`connect` を宣言したスコープに含まれること |
| 秘密 | ハンドル・注入の各スコープが、`secret:read` を宣言したスコープに含まれること |
| マウント | 各マウントのスコープが、`filesystem` を宣言したスコープに含まれること |

- 宣言から導いたプロファイルは**違反なし**（試験で固定）。
- 宣言に無い接続先・マウント・秘密は**違反として報告**。

**まだ `HostSandboxLauncher.Invoke` から呼んでいません**。呼ぶようにすると、宣言より広いプロファイルでの実行が拒否されます。既存の試験のプロファイルがこの条件を満たすかを見てから配線します。
