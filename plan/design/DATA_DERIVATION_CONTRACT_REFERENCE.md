# データ導出規則の最小意味契約（#1637）

> 状態：採用前の設計・参照試験計画。実装済み機能・原X-TEA Driverとの同等性を主張しない。
> 基準：main `cacf46a4a27cfb48081bc20503780e999ce51cf8`（2026-10-13確認）。

## 問題と責務

X-TEA Driverの仮想項目とテーブルスクリプトが担う読み取り時の値導出を、特定の実行順・言語・物理列に固定せずTEIの業務意味へ接続する。従来のBR/ARイベント名は標準契約へ持ち込まない。原Runtimeで実際に何が起こるかの検証は #940 が担当する。

- **規則の定義**：計算の安定ID、入力への型付き参照、結果の意味型、純粋性、演算子／実装への参照、依存関係、規則版。
- **適用先との結び付け**：規則IDと、意味属性・問い合わせ局所結果・集合集計などの適用先IDとスコープ。属性名やSQL列名の一致から結び付けを推定しない。
- **実行時の文脈**：対象行、参照関係、許可された入力、入力の取得状態、評価時点。規則本文に接続情報・資格情報・権限を保存しない。

`DerivationDefinition` と `DerivationBinding` は議論上の仮称。新しいCore型、DSL構文、汎用式エンジンの採用を意味しない。既存のSemantic ID (#1120)、演算子契約 (#988)、受理・Lowering (#1121)、Authority (#1118/#1174) を再利用する。

## 評価結果の最小区別

| 状況 | 期待する扱い |
| --- | --- |
| 入力が存在し計算可能 | 型付きの値を返す |
| 入力が業務上のNULL | 宣言されたNULL方針に従う。暗黙の0置換は禁止 |
| 必要な入力を取得していない | NULLと混同せず、評価不能または入力不足として報告 |
| 期待する参照先が0件 | 未取得と区別し、参照の多重度・欠損方針に従う |
| 一対一を期待する参照先が複数件 | 先頭の1件を暗黙に採用せず拒否 |
| 型不一致・演算子未解決 | 診断付きで失敗。代替実装へ黙って切り替えない |
| 依存循環 | 評価前に拒否 |
| 副作用の要求 | 純粋評価では拒否。更新・Commit後処理は #1129 |

上記は概念的な状態区別であり、巨大な共通enumを先に作らない。NULLは正当な値の状態、未取得は実行・参照の問題として区別する。精度・丸め・通貨単位の一致は演算子契約で確認する。

## 参照シナリオ（自作の合成データ）

1. `quantity=2, unit_price=300` → `amount=600`。
2. `quantity=0, unit_price=300` → `amount=0`。
3. `quantity=NULL` → 宣言されたNULL規則の結果。0と同一視しない。
4. `unit_price`未取得 → 入力不足。値NULLと区別する。
5. 単一参照が0件、または2件一致 → 異なる診断。恣意的な先頭選択なし。
6. 規則A→B→A → 循環として拒否。
7. 文字列×金額型などの不正な入力、演算子未解決、副作用要求 → 拒否。
8. 同じ規則を意味属性とQuery局所結果に結び付ける → 規則の正本は一つ。適用先の権限・スコープはそれぞれ評価。

### 試験と証拠

最初は独立した最小のGo参照実装・表形式の試験で規則定義と適用先の分離を圧力試験する。参照試験の成功は、Canonicalへの受理、Providerでの実行、原X-TEA Driverとの動作同等性の証拠ではない。実施した試験名・結果・未検証事項をPRに記録する。

## 後続課題と非目標

- #1641（D3）：導出結果・キャッシュ・確定保存値を区別。単純な導出へ高度な鮮度宣言を必須としない。

- #1180：シナリオ試験の正本を複製しない。

汎用SQL最適化、全SQL方言への自動変換、JavaScript互換、汎用キャッシュ、無条件のCanonical型追加は本設計の非目標とする。
