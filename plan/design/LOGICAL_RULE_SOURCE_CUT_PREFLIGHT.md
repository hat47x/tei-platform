# 候補キー・関数従属性の撤回に向けた正本ソース範囲の特定（#1126）

状態：**撤回前の出所照合・バイト範囲の計算だけを提供する参照機構**。現在のShared Acceptanceに撤回／更新の型付きdeltaは追加しない。

## 背景

PR #1536によって既存Dataへの論理候補キーと関数従属性の追加がShared Acceptanceを通るようになった。一方、削除や改訂は、Source上の宣言そのものを取り除く必要がある。単純な文字列検索や最後の閉じ波括弧を探す実装では、別のDataの規則や隣接する宣言を誤って削除する危険がある。また、PR #1586は旧Worldからの影響解析を先に独立して改善中のため、その変更には依存しない小さな実装に分ける。

## 今回の機構

`planBusinessRuleSourceCut(content, kind, dataID, ruleID)`はソースの実バイト列に対して次を検証する。

- CanonicalなData・規則IDを要求し、規則の種類を`candidate-key`または`functional-dependency`のみに制限する。
- 正本Semanticパーサーとアンカーパーサーの両方を通し、対象のDataとその規則が一つだけ存在し、規則IDの出所位置も一意であることを要求する。
- 定義位置の識別子トークンを起点に、規則が対象Dataの**直下**にあることを波括弧の深さで検証する。
- 対象の規則の開始行から、対応する閉じ波括弧と行末までの範囲だけを切り出す。前後のソースはバイト単位で保持し、CRLFも変換しない。
- 構文不整合、重複定義、他Data参照、同じ行に別の記述やコメントがある場合は推測せず拒否する。切り出し後もSemantic構文を検証する。
- 削除対象の識別子範囲、全ブロックの切出範囲、切り出した原文、変更前後のSHA-256指紋を`BusinessRuleSourceCut`に格納する。

## 非目標と安全境界

- 本関数は**ファイルを書き込まない**。撤回の意思決定、ユーザー権限、Shared AcceptanceのPreview／Review／Accept、基準Worldの版検査は別のレイヤーで扱う。
- 出力する`after`は後続処理の試案であり、正式な差分や採用済みSourceではない。提出された規則が実業務で誤りだったことも推論しない。
- 正式な撤回操作は、PR #1586の旧World参照付き影響解析、既存のSource fingerprint検査と結合し、旧規則の影響・根拠・人間による確認を表示してから受理する。
- 本関数はDataのSource fileを探さない。ファイル探索・所有者の検証はWorkspace Load／Source Indexで行い、選ばれた**その1ファイルのバイト列**を渡す。

## 試験

正本内の別DataやFDを保持した候補キーの切出し、CRLF、位置・SHA指紋、再切出し拒否、誤kind/owner/ID、重複Data、構文不整合、インライン宣言・終端コメントの拒否、入力不変性を検証する。

この結果は、撤回操作の安全性を成立させるための一部にすぎない。現時点で撤回を製品機能として利用可能とは記載しない。
