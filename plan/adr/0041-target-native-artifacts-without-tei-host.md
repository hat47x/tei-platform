# ADR-0041: TEI独自Hostを前提とせず、成果物を対象環境に適応させる

- **状態**：採用（設計方針、2026-10-24）。実装済み・検証済みという意味ではない。
- **判断主体**：TEI Owner（2026-10-24の設計議論）。
- **関連**：[ADR-0032](0032-composition-kernel-replacement.md)、[ADR-0033](0033-core-and-plugin-subprojects.md)、[ADR-0036](0036-delivery-forms-as-plugin-composition.md)、[製品要求](../../requirements/TEI_PRODUCT_REQUIREMENTS.md)。
- **更新範囲**：ADR-0032の「最小Host機構を共通の前提とする」部分と、ADR-0033の「コアが最小ホスト機構を含む」という目標配置を更新する。契約識別、合成、来歴、受理、実行時の権限、副作用、結果・不確実性の区別について、既に成立した根拠や未決事項を取り消すものではない。

## 背景

TEIの成果物は、既存の.NETアプリケーション、JVM上のJavaアプリケーション、Web、OS上のプロセス等へ組み込まれることがある。これらの上にTEI独自の共通Hostを重ねると、既存のライフサイクル、認証認可、実行管理、監査と責務が重複する。単独の高性能ネイティブバイナリを生成する場合にも、追加の共通実行機構が最適化の制約となり得る。

## 決定

1. **TEI独自の共通Hostを構築対象・必須前提としない。** TEIが中心的に提供するのは、Data / Function / Business等の意味の記述・関係付け・検証と、ターゲットに適した実装の生成・構成・検証である。既存ソース中の `Host` / `Runtime` 等の名称を、そのままTEIの将来アーキテクチャ上の必須要素とはしない。
2. **成果物は実行環境へ適応する。** .NETのDLL等、Javaのクラス/JAR、ブラウザ用資産、Wasm、既存アプリケーションに組み込む部品、単独ネイティブ実行ファイルなどを選べるようにする。対象環境が提供するライフサイクル・機能は再利用し、単独バイナリでは必要な実装を内部に包含する。生成時の静的結合、未使用実装の除外、コンパイル時最適化を妨げない。
3. **関心と解決タイミングを分ける。** 認証、認可、Capability、外部副作用、Transaction、監査、分散実行は、それぞれの契約、提供主体、境界、発生時点に応じて解決する。意味上の保証をモデルで共有できても、共通プロセスや共通ランタイムへの集中配置は要求しない。EKI等の専門製品との連携も選択肢である。
4. **信頼形成と検証を組み合わせる。** 本番に採用するライブラリ・Pluginは、提供組織・保守・流通経路の信頼性を評価し、必要なら独自に設計・コード・依存関係を検証する。生成AIは解析、比較、反例・試験作成を支援し、言語系・静的解析・動的試験は再現可能な証拠を補う。これらだけで組織的な採用判断を置き換えたり、未知の欠陥がないと断定したりしない。Plugin由来のプロンプトインジェクションはAIが外部資料を読む信頼境界の問題として個別に扱う。
5. **受理と実行許可の境界を維持する。** Source fact、Proposal、Acceptedな業務意味を区別し、Ownerが受理するBusiness Actionの意味と、実際の副作用を行う主体が強制する現在の実行権限を区別する。既存のValidation、Effect、Outcome、rollback/replay、監査の必要条件は、適切な対象環境に実装・接続されて初めて満たされたと扱う。Debugの検証結果は本番実行の全保証とみなさない。
6. **名称と実装事実を区別する。** Studioの開発用Host、既存のGo Web Host、参照用Process Hostなどは実装・試験の事実として記録を残す。これらをTEIで生成するすべての製品の必須Hostとして一般化しない。

## ADR-0032 / ADR-0033との関係

ADR-0032のService Contract、Provider、Consumer requirement、Composition Profile、Scope、静的・動的構成の検討は継続する。ただしHost局所Generation、Root of Trustを担う最小Host、Hostを中心としたM3/M4の移行経路は、**そのような実行環境を選択した場合の設計・検証対象**であり、TEI全体の共通実行基盤を導入する計画とはしない。

ADR-0033のサブプロジェクト管理、依存方向、生成物と配備単位の分離は継続する。`core/`に最小Hostを置くという記述は、このADRによって更新される。開発ツールの実行入口や既存実装が残ること自体は妨げない。

## 検証と未完了の範囲

- 既存.NET / Java側へ埋め込む成果物と単独ネイティブ成果物について、利用側のライフサイクル、権限、結果、失敗・不明、副作用の責務を追跡し、不要なTEI Hostを要求しないことを確かめる。
- 同一のAccepted meaningから、ターゲット別の生成・検証根拠とArtifact来歴を追跡する。静的結合が実際に速度・サイズで有利かは測定して判断する。
- 現行の`Host`系コード・Reference・Issue・ADRに残る接続と未接続は、既存の証拠時点を保持したまま再評価する。文書の更新をRuntime移行、実Provider/DB受入、Windows GUI受入の完了とみなさない。
