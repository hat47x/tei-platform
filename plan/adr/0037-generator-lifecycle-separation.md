# ADR-0037: 生成器の失効・置換を、意味・生成物・実行受理の版から分離する

- 状態: 提案中
- 日付: 2026-10-19
- 関連ADR: ADR-0022 / ADR-0034 / ADR-0035
- 関連Issue: #2016 / #951 / #1109 / #1370 / #943
- 関連実装: [`tools/reference-generator-selection/`](../../tools/reference-generator-selection/README.md)

## 背景

ADR-0034は、生成器を受理済み意味から導出する版付き成果物として扱い、失効と再生成を追跡する方針を示した。しかし、参照実装では生成器registryに`active`と`revoked`しかなく、次の問いに答えられなかった。

- 新しい版に置き換えただけの生成器と、危険なので使ってはならない生成器を、同じ「使えない」に潰してよいか。
- 生成器を失効させたとき、その生成器が過去に出した生成物や、受理済みの意味はどうなるか。
- 契約が変わった生成AI候補を、別の契約の証拠として再利用してよいか。
- 失効した生成器の生成物を、現在の適合証拠として使い続けてよいか。

## 判断

### 4つの版を分ける

少なくとも次を、別のidentityと版として扱う。

1. **意味の版**: 受理済みの契約・Workspace revision
2. **生成器の版**: 契約からsourceを生成する成果物の版
3. **生成物の版**: 生成器と入力から得られた候補・成果物
4. **実行受理の版**: Hostが現在許可しているProvider・artifact・権限

生成器の失効は2に対する判断であり、1・3・4の版を自動的に失効させない。反対に、生成器がactiveであっても、3の生成物が現在の契約・fixtureに適合するとは限らない。4は別のAuthorityが所有する。

### 置換と失効を区別する

- `superseded`: 後継の版へ置き換えられた版。履歴として残し、現在の生成には使わない。
- `revoked`: 使用してはならない版。置換の有無にかかわらず、現在の生成・選抜に使わない。

両方を「使えない」と表示するだけでは、利用者は後継へ移行すべきか、原因を調査すべきかを判断できない。registryは`supersedes`と`reason`を記録し、後継の欠落・二重の後継・循環を拒否する。

### 生成AI候補を契約へ束縛する

生成AI候補の`generation`は、prompt・context・outputだけでなく、候補を作った契約のdigestを持つ。選抜は現在の契約digestと照合し、別契約の候補を現在の証拠として使わない。

これは生成AIを特別に扱う規則ではない。テンプレート生成器の`generator.contractDigest`と同じく、候補の出所と入力契約を分離しないための一般的な束縛である。

### 影響の確認と、再生成・再選抜を分ける

`reconcile`は、registryのactive版と候補directoryを比較し、`current`、`stale-version`、`stale-source`、`stale-contract`、`superseded`、`revoked`、`unregistered`を区別する。これは影響の報告であり、選抜・適合・受理ではない。

再生成した候補は、固定fixtureによる選抜をやり直す。古い合格結果を、新しい生成器・契約・成果物の証拠へ流用しない。失効の承認、再生成の実行、候補の採用は自動化しない。

### registryを権威にしない

registryはプロジェクトが現在の版を宣言する制約であり、意味の受理、Provider適合、Hostの実行許可、本番配備の権限ではない。`passed=true`や`active`は、それらの代替にならない。

## 代替案

- **失効だけですべてを表す**: 置換と危険な失効を区別できず、移行経路を示せないため採用しない。
- **生成器を失効させたら、その生成物と意味も失効させる**: 意味の受理と生成器の不具合を混同し、過去の証拠を破壊するため採用しない。
- **契約digestを生成AI候補に記録しない**: 別契約の候補を現在の証拠として再利用でき、fail closedにならないため採用しない。
- **reconcileで自動的に再生成・再選抜する**: 新しい候補の選抜と受理を迂回するため採用しない。

## 影響

- registryはv0（active/revoked）を読み続け、v1で置換を含むライフサイクルを表現する。
- 生成AI候補の`generation`へ`contractDigest`が加わる。旧候補は現在の契約へ再束縛するか、再生成が必要になる。
- 生成物の削除・置換・再生成の判断は、`reconcile`の報告と通常の選抜を経て行う。
- 署名・build provenance・失効の承認主体は、ADR-0034と#943 / #1370の範囲として残る。

## 未決

- 失効を誰が承認し、どの単位で記録するか。
- 後継の版を自動提案するか、人が明示するか。
- 生成器の版と生成物の版を、既存のArtifact/Build Evidenceへどう載せるか。
- 失効した生成器が過去に出した生成物を、監査・再現のためにどこまで保持するか。

## 検証

#2016の参照実装で、次を確認する。

- v1 registryがactiveな後継だけを解決し、superseded・revokedを区別する。
- 置換先の欠落、二重の後継、循環、理由のない失効を拒否する。
- superseded・revokedの候補を選抜で拒否する。
- 別契約で記録した生成AI候補を、現在の契約の証拠として拒否する。
- `reconcile`がstaleな候補と不足している生成器を示し、再生成後も選抜を要求する。

この検証は、意味の受理、実Provider、実Target、本番配備を証明しない。効果が確認できない場合は、registryのlifecycle項目を参照実装の範囲へ戻す。
