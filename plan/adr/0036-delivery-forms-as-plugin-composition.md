# ADR-0036: 提供形態の違いはプラグインの選択で実現し、形態別の実装を作らない

- 状態: 採用
- 日付: 2026-10-19
- 関連ADR: ADR-0031 / ADR-0032 / ADR-0033
- 関連Issue: #2020 / #2019 / #1043 / #1223

## 背景

TEIは、個人の開発、SIerの受託開発、大規模SaaSの運用という異なる提供形態を対象にする。提供形態ごとに、テナント分離、認証、配布、監査、保存、課金の必要性が変わる。

ここで形態ごとの専用実装や専用ビルドを作ると、同じ意味の変更が形態ごとに分岐し、検証と移行の再利用が効かなくなる。TEIの価値である「同じ意味から複数の実現を選ぶ」ことと矛盾する。

## 判断

### 提供形態をプラグインの選択として扱う

提供形態は、Coreの意味・実行契約に対する**プラグインの選択と構成**で実現する。形態別のアプリケーション実装、形態別のCore分岐、形態別の第二の正本を作らない。

```text
Canonical meaning / Core contracts
        +
selected delivery plugins
  - tenant isolation
  - authentication / authority
  - storage / data residency
  - distribution / export
  - audit / observability
        |
application / target
```

### SaaSはテナント分離の基盤機構を提供する

SaaS向けに、テナント分離を実現する基盤機構をプラグインとして提供する。アプリケーションはその機構を利用し、アプリケーションごとにテナント分離を再実装しない。

基盤機構は少なくとも次を扱う。

- テナントの識別と、テナントごとの保存領域の分離
- テナントを越えた参照・書込みの拒否
- 現在のテナントと権限の明示
- 越境の試行と拒否の記録
- テナント分離を提供できない場合のfail closed

### 個人・SIerの違いもプラグインで表す

- 個人向けは、ローカル保存、オフライン動作、単一利用者の権限を提供するプラグインを選ぶ。
- SIer向けは、顧客ごとの配布、エクスポート、権限の委譲、監査証拠の受渡しを提供するプラグインを選ぶ。
- 大規模SaaS向けは、テナント分離、段階的更新、監査、データ所在を提供するプラグインを選ぶ。

形態固有の要件はプラグインの契約へ置き、Coreへ形態名やテナント固有の分岐を追加しない。

### Delivery Profileは選択と検証だけを行う

Delivery Profileは、提供形態に必要なプラグインと能力を宣言し、選択された構成が要件を満たすかを検証する。Profile自体は実装を持たない。

必要な能力が不足している場合は、形態別の実装を追加するのではなく、その構成を拒否するか、能力を持つプラグインを選び直す。

## 代替案

- **提供形態ごとに別のアプリケーションを作る**: 意味と検証が分岐するため採用しない。
- **一つの万能プラグインですべての形態を扱う**: 形態固有の制約をCoreへ押し込み、分岐を招くため採用しない。
- **Profileを第二の正本にする**: 意味の正本と構成の宣言が混ざるため採用しない。

## 影響

- プラグインの能力・分離保証・権限・失敗時の扱いを契約として記述する必要がある。
- テナント分離の基盤機構を、アプリケーションから利用できる形で提供する必要がある（#2020）。
- Delivery Profileの検証と、プラグイン構成の解決が必要になる。
- 形態ごとの専用ビルドを前提にした運用手順は見直しが必要になる。

## 未決

- プラグインの配布・課金・契約管理をどこまでTEIが扱うか。
- テナント分離の保証を、DB・ファイル・外部APIのどこまで強制するか。
- 形態をまたぐ移行（個人→SaaS、SIer納品→SaaS）の手順。

## 検証

#2020で、二つのテナントと同じアプリケーション意味を使い、テナント分離の基盤機構が越境参照・越境書込みを拒否することを最小Referenceで確かめる。形態別のアプリケーション実装を追加せずに成立することを確認する。
