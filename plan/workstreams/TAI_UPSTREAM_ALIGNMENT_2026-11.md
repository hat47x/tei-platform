## 1. TAIが定めているTEIの役割

TAIの責務境界は、TEIの役割を「業務データ・規則候補のモデル化と検証」とし、TAI側に「承認された規程との対応が必要かの判断」を残します。TEIはSCN-001の案内文を作る基盤ではなく、**規程候補の意味をモデル化し、検証できるか**を担います。実データ・実実行先・受理は未確認のままです。

TAIは同時に、六つの失敗時の動作を定めています。TEIの設計はこれを破ってはいけません。

| TAIの失敗時の動作 | TEI側で対応する仕組み |
| --- | --- |
| 読めないときは「未確認」として保留する | 操作面の `missing-input`、成果物の `Unresolved` |
| 相反する観測は双方残す | 期間の状態・観測の記録（上書きしない） |
| 発見と、呼べる・正しく動くことを分ける | 操作面は「読み取れる」だけ。実行は認可・効果の境界を通す |
| 権限が未確認なら公開・状態変更を停止する | 自律区分の `human-gated`、`closed` 期間の拒否 |
| 成功コードと独立した成果の観測を区別する | 実行計画の `finished` と独立した観測、#1127 の観測受入 |
| 同内容への復帰は旧判断の復活ではない | 期間の `reopen` と、SEIの判断の有効性を混同しない |

## 2. 三要素の見方

上流へ戻るときは、各課題を次の三つに分けて見ます。症状の箇所だけを直さず、同じ判断をした他の箇所へ同じ修正を広げるための道具です。

- **対象**: 何を扱っているか（業務データ、規則、期間、成果物）。
- **関係**: 誰と・何と結び付いているか（他の製品、他の課題、実行先、利用者）。
- **境界**: どこまでがTEIの意味で、どこからが他の製品・実行先・人の判断か。

## 4. 越境の検査から出た修正

1. **#1129**: 効果規則に「誰の判断で」を持たせない。判断の識別子を参照するだけにし、判断の来歴・有効性はSEIへ置く。設計文書の「所有者」は**保存の所有者**（どのアプリケーションが保存するか）であり、判断の所有者ではないと明記する。
2. **#1130**: `run-plan` の適用範囲を「同じアプリケーションの内側で完結する実行」に限定する。外部への委任が必要になった時点でEKIへ渡し、TEIは委任の必要性を判断しない。無人の実行の宣言は、TEIの内側の実行にだけ効く。
3. **#2144**: `reopen` は期間を開き直す操作であり、過去の判断を有効に戻す操作ではない。判断の有効性はSEIが持つ。締めの記録は「いつ・どの時点を切り出したか」だけを持つ。
4. **#1803**: 成果物は設計の確認のためのもので、読み手向けの文書（案内文・对外報告）はSHOが作る。TEIは成果物の内容と未解決を持ち、体裁・配布・公開の判断を持たない。

## 6. この整合で変えないこと

- TAI側の文書・契約・状態。TEIから提案はするが、TAIの正本は変更しない。
- 各製品の実装。境界の整理であり、SEI・EKI・SHOの機能をTEIへ取り込まない。
- 判定段階B・Cの合格条件。境界の整理は合格条件を緩めない。
