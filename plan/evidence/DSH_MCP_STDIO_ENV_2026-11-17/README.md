# stdioの`env`は継承環境に**足す**だけでなく**上書き**もできる。ただし**消す**ことはできない（2026-11-17、#2515 H6-E2）

- 対象Issue: [#2515](https://github.com/hat47x/tei-platform/issues/2515)の`H6-E2`と`#2509`の経路網羅。機密境界の正本は[TAI #232](https://github.com/hat47x/tai-pleroma/issues/232)。
- 実行日: 2026-11-17（Asia/Tokyo）
- 実行環境: Windows 11 Pro `10.0.26100`（AMD64）、DSH `0.2.2-rc.3`（`dsh --profile headless`）、Node `24.21.0`
- 状態: **ローカルの合成MCPサーバーのみ**。実MCPサーバーへの接続は**NOT RUN**。
- 先行記録: [MCPのstdio経路](../DSH_MCP_STDIO_2026-11-10/README.md)（環境の継承を見たが`env`明示は未確認）。本記録は、そこで未確定とした「**`env`設定で明示的に渡した場合**」を埋める。

## 1. 何をしたか

**同じstdioのMCPサーバー**を4通りで起動し、**子Process自身の環境**を記録した。親には**`STDIO_ENV_CANARY_997=CANARY_VALUE_997`**を置いた。

| 実行 | `env`の設定 |
| --- | --- |
| **A** | 新しい2変数を追加（`EXPLICIT_ENV_ONE`・`EXPLICIT_ENV_TWO`） |
| **B** | **`env`を書かない**（基準） |
| **C** | **継承済みの値**を別の値へ上書き |
| **D** | **継承済みの値**を**空文字**にする |

## 2. 観測した結果

### 足す（A と B の比較）

| 実行 | 環境変数の数 | 追加されたキー | 消えたキー |
| --- | --- | --- | --- |
| **B（`env`なし）** | **49** | — | — |
| **A（2つ指定）** | **51** | **`EXPLICIT_ENV_ONE`・`EXPLICIT_ENV_TWO`** | **0** |

- **49個はそのまま残り**、**指定した2つが加わった**。**置換ではなくマージ**である。

### 上書きできる（C）

```
STDIO_ENV_CANARY_997 = "OVERRIDDEN_BY_CONFIG"
```

- **継承した`CANARY_VALUE_997`は残らず**、**設定した値になった**。**`env`は上書きもできる**。

### 空にはできるが、消せない（D）

| 項目 | 値 |
| --- | --- |
| 変数は存在するか | **する**（`targetPresent: true`） |
| 値 | **`""`（空文字）** |
| 継承値は残っているか | **残っていない** |

- **値を空にすることはできる**。つまり**中身は消せる**。
- ただし**キー自体は残る**。**「変数があるか」で判定する検査は、空にしても通ったままになる**。

## 3. この記録が示すこと

- **`env`は加算的ではない**。**継承した値を上書きでき、空にもできる**。
- **削除はできない**（**推論**）。**削除の書式が無く**、**空にしてもキーが残った**ことからそう判断した。**削除を試した実行は無い**。
- 機密の観点では、**継承された秘密らしい変数を設定から無害化できる**（空にする）。一方で、**「その変数が存在しない」状態は作れない**ので、**存在チェックを根拠にした統制は空文字で迂回されうる**。
- **DSH自身のモデル資格情報（`DEEPSEEK_API_KEY`）は、子の変数一覧に無い**。ただし**これはAとBの2実行での観測**である（CとDは変数一覧を記録していないため**未確認**）。**親には設定してあった**ので、**継承されなかった**ことは言える。

### 途中で自分の読みを訂正した

**Aだけを見た時点では「`env`は足すだけ」と結論しかけた**。CとDを足したことで、**上書き・空化もできる**ことが分かり、**結論を「足す＋上書きできる／消せない」に直した**。**1つの実行から一般化しない**という点で、この記録自体が例になっている。

## 4. この記録が示さないこと

- **キー名の大文字小文字**の扱い（Windows）。
- **広い変数集合での掃引**（本記録は4通り・対象1つ）。
- **子Processが親環境を別の手段で読めるか**（本記録は起動時に渡る環境のみ）。
- **`cwd`設定**との組み合わせ。
- 実MCPサーバー、サーバー側の保存。
- `H6-E2`の合否、機密Profile適合、Owner受理、#1119のGate。

## 5. 生データ

| ファイル | 内容 |
| --- | --- |
| `stdio-env.json` | `experiment`、`runA_explicitEnv`／`runB_noEnv`／`runC_overrideInherited`／`runD_blankInherited`、`mergeAnalysis`（追加・削除・共通キー数・結論）、`answers`（マージ／上書き可否／空化可否／削除可否）、`securityImplication`、`correctedFromEarlierReading`、`caveat` |

**環境変数の値そのものは保存していない**（キー名・個数・判定フラグのみ）。**合成のみ**（`STDIO_ENV_CANARY_997`・`EXPLICIT_ENV_*`）。

再現する場合の要点:

```yaml
- insert:
    - id: mcp-client-envprobe
      name: "@deepseek-ai/dsh-mcp-client"
      config:
        transport: stdio
        serverName: envprobe
        command: python
        args: ["<script>", "<record-dir>"]
        env:
          STDIO_ENV_CANARY_997: ""     # D: 空化
          # STDIO_ENV_CANARY_997: "OVERRIDDEN_BY_CONFIG"   # C: 上書き
```

- **子Process側で自分の環境を記録する**。親側の設定を見ても、**実際に渡ったかは分からない**。
- **値をそのまま保存しない**。**一致判定の真偽値だけ**を残す。
- **`env`なしの基準を必ず取る**。基準が無いと「足したのか置換したのか」を区別できない。

## 6. `H6-E2`への含意（判断はしない）

`env`は**上書きできるが削除できない**。したがって**「この変数は渡っていない」を作る統制には使えず**、**「値を無害化する」統制には使える**。どちらを求めるかで有効性が変わる。どの統制を採るかは#2515とTAI #232のOwner判断であり、本記録は判定しない。
