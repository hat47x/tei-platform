## 6. 試験自体の欠陥を2つ踏んだ（記録）

**このラウンドで、私が書いた試験が2回「静かに通る」状態になった。**

## 9. 付随して見つけた既存試験の潜在欠陥

`tools/repository-plan-check/plancheck_test.go` の `itoa` は**1桁しか正しく変換しない**。

```go
func itoa(n int) string {
	return string(rune('0' + n))
}
```

`n = 514` は `rune('0' + 514)` = `U+0232`（`Ȳ`）になり、失敗メッセージの行番号が文字化けする。私は最初この helper を再利用して実際に `Ȳ` を得た。

現在の呼出し元は ADR 番号や Issue 番号（1桁〜3桁）を渡しているため、**3桁以上で化ける**。本ラウンドでは自分の試験に `strconv.Itoa` を使い、`itoa` は変更していない（既存試験の挙動を変えると影響範囲が読めないため）。#3919 に所見として記録した。
