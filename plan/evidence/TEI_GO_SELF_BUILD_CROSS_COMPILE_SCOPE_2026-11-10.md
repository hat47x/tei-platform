# `darwin`・`arm64` で何が確かめられ、何が確かめられないか

[#2831](https://github.com/hat47x/tei-platform/issues/2831) のSB-C0 §7 は「`darwin`・`arm64`・別のGo版の組合せでの観測」を未決として残しています。§4.26 は `linux/amd64` と `windows/amd64` の二つで四つの照合値が一致することを実測しました。本記録は、**このホストで残りの組合せについて何が確かめられるか**を測ります。

> **後続の記録で、この結論のうち `arm64` については覆されました。** 当時は「このホストにエミュレータが無い」と判断しましたが、`multiarch/qemu-user-static` の静的バイナリを**root なしで**入手でき、`arm64` は実行で観測できるようになりました。解決の値（[実測](TEI_GO_SELF_BUILD_ARM64_RESOLUTION_2026-11-10.md)）、Go版との2×2（[実測](TEI_GO_SELF_BUILD_GO_VERSION_AND_ARCH_MATRIX_2026-11-10.md)）、連鎖全体の Claim（[実測](TEI_GO_SELF_BUILD_ARM64_L2B_CHAIN_2026-11-10.md)）が続いています。**`darwin` は依然として実行できません。**

**当時の結論：`darwin` も `arm64` も実行による観測はできません。** できるのはビルドと静的検査までです。以下はその時点の観測です。

## 実測：クロスコンパイルは通る

| target | ビルド | サイズ |
| --- | --- | --- |
| `darwin/arm64` | **成功** | 27,609,378 B |
| `darwin/amd64` | **成功** | 29,299,776 B |
| `linux/amd64` | 成功 | 28,787,005 B |
| `windows/arm64` | **成功** | 26,835,456 B |

`file` で確認したところ、`darwin/arm64` の出力は本物の Mach-O だった。

```
/tmp/tei-darwin-arm64: Mach-O 64-bit arm64 executable, flags:<|DYLDLINK|PIE>
```

**これは「コンパイルが通る」以上のことを言いません。** §4.26 が確かめたのは**実行して四つの照合値が一致する**ことであり、ビルドの成功はその代わりになりません。

## 実測：解決ロジックにホスト依存の分岐が無い

四つの照合値（`intentFingerprint`・`sourceClosure`・`planFingerprint`・`artifactDigest`）を生むパッケージを調べた。

| ファイル | `runtime.GOOS`・`runtime.GOARCH`・`os.Getenv`・`filepath.FromSlash` |
| --- | --- |
| `internal/buildintent/resolve.go` | **0件** |
| `internal/buildintent/catalog.go` | **0件** |
| `internal/buildintent/intent.go` | **0件** |

**ホストごとに分岐する箇所が無い**ので、値が変わる理由をコードの中に見つけられません。これは「一致するはずだ」という**推論の材料**であり、一致の観測ではありません。

## 実行できない理由

| 必要なもの | 状況 |
| --- | --- |
| macOS の実行環境 | **無い** |
| `qemu-aarch64`（arm64のエミュレーション） | **無い**（`/usr/bin/qemu-aarch64*` が存在しない） |
| 2つ目の Go 版 | **無い**（`/usr/local/go` の `go1.27.3` とWindowsの `go1.27.0` のみ） |

**`darwin` バイナリは Linux 上で動きません。** クロスコンパイルは出力を生成しますが、その出力をこのホストで走らせる手段がありません。

## §4.26 との関係

| 項目 | §4.26 | 本記録 |
| --- | --- | --- |
| `linux/amd64`・`windows/amd64` の**実行**と一致 | **観測済み** | — |
| `darwin/arm64`・`darwin/amd64` の**ビルド** | 範囲外 | **確認した** |
| `darwin`・`arm64` の**実行**と一致 | 範囲外 | **できない** |
| 解決ロジックのホスト非依存 | 未確認 | **静的確認した** |

**§4.26 の主張は強まっていません。** 「二つのホストで一致した」はそのままです。本記録が足したのは「他のホストではビルドが通る」と「コードに分岐が無い」の二点で、どちらも**実行による裏づけではありません**。

## §7 の項目をどう扱うか

**未チェックのままにします。** 理由は三つ。

1. **実行していない。** ビルドの成功は §4.26 が測った性質の証拠にならない
2. **環境が無い。** 当時はこのホストで実行する手段が無く、待っても埋まらないと判断しました（`arm64` については後続の記録が覆しています）
3. **項目を取り下げる根拠も無い。** 「できない」は「不要」ではない

代わりに、**この記録を§7の項目から参照**して、「何が確かめられていて何が確かめられていないか」を読み手が判断できるようにする。

## 何を言っていないか

- `darwin`・`arm64` で値が一致する、とは言っていない。**確かめていない**
- 一致するはずだ、という推論もしない。**コードに分岐が無い**という事実だけを書いた
- ビルドが通ることを「対応している」と読み替えない。**対応の主張には実行が要る**

## 検証

- `GOOS/GOARCH` を変えた `go build ./cmd/tei` が4つの target で成功
- `file` による出力形式の確認（`darwin/arm64` が Mach-O arm64）
- `internal/buildintent` の3ファイルに host 依存参照が0件（機械的検索）
- 環境の実測：`qemu-aarch64` 無し、Go 版は 2つ

**NOT RUN**：`darwin`・`arm64` 上での実行、四つの照合値の比較。環境が無いため。

## 限界

- **ビルドの成功は実行の成功ではない。**
- 静的検索は `internal/buildintent` の3ファイルに限る。CLI や他パッケージは調べていない。
- arm64 の**実機**で動かせば別の結果が出る可能性を否定できない。
- G4は `UNQUALIFIED` のまま。
