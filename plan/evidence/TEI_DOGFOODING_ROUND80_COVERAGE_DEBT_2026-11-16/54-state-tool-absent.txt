So the state is declared and branched on but never produced by Receive. The REA
test that fails on main says the same thing from the other side:
TestReaEvidenceRecordsTheToolAbsence expects state=complete with an absent tool,
because the saved bytes are still whole; absence lives in Receipt.Tool.

Rather than delete the constant (the two callers are written to accept it) or
invent a producer, the new test pins the decision from both sides:

  state stays complete when the tool is absent
  Receive does not produce StateToolAbsent
  Tool.Present / Tool.AbsentReason carry the absence
  the raw fingerprint survives
  a present tool and an absent tool have the SAME state
