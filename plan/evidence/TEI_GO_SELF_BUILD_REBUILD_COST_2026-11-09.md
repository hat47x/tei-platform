# `-rebuild-check` の実測コスト（§4.25 が挙げた欠測の補完）

[#2831](https://github.com/hat47x/tei-platform/issues/2831) のSB-C0 §4.25は、三つの未決を一つの判断として扱う案を示し、**「実buildの所要時間は測っていない」**と明記しました。本記録がその欠測を埋めます。

**判断は下しません。** §4.25 の P-1〜P-4 に、実測値を一つ足すだけです。

## 実測環境

| 項目 | 値 |
| --- | --- |
| OS | WSL2 Ubuntu-22.04 |
| Go | `/usr/local/go/bin/go`（native linux/amd64） |
| 対象 | `cmd/tei`（`go build` した実行物） |
| builder child | `tools/reference-plugin-package-build-child` |
| catalog | `tools/reference-build-authoring-intent/testdata/catalog.json` |
| 宣言 | `tools/reference-build-authoring-intent/testdata/intent.json` |
| 試行回数 | 各5回、state と出力先は毎回別 |

## 実測値

| 条件 | 1 | 2 | 3 | 4 | 5 | 平均 |
| --- | --- | --- | --- | --- | --- | --- |
| `-rebuild-check` なし | 196ms | 188ms | 194ms | 199ms | 184ms | **192ms** |
| `-rebuild-check` あり | 281ms | 294ms | 415ms | 390ms | 354ms | **346ms** |

**比 = 1.80倍**（346 / 192）。

## 何が分かったか

**「ほぼ二倍」は概ね正しいが、正確には1.8倍。** §4.25 は「build時間をほぼ倍にする」と書きました。実測は1.80倍で、倍率は1未満に収まっています。

**差は約154ms。** 二回目のchild起動と一時ディレクトリの作成が主な内訳と考えられますが、**内訳は測っていません**（計測点を分けていないため）。

**ばらつきは rebuild 側が大きい。** plain は 184〜199ms（幅15ms）ですが、rebuild は 281〜415ms（幅134ms）です。二回目の起動が入る分、FS や scheduler の影響を受けやすい構造になっています。**幅を無視して平均だけを比べるべきではありません。**

## §4.25 の判断への影響

| 案 | 実測を踏まえた所見 |
| --- | --- |
| P-1（現状維持） | 192ms/試行。速さを優先するならこれ |
| P-2（再現だけ既定） | **全試行が346ms**。child経路でもclaimは立たないので、コストだけ増える |
| P-3（両方既定） | 346ms＋catalog 3点セットの準備。**呼び手の義務が増える** |
| P-4（既定は軽く、flagで強く） | 192ms を既定に保ち、強い試行だけ346ms |

**P-2の非対称性が数字で裏づけられました。** child経路では主張が増えないのに、154ms（1.8倍）を全試行で払うことになります。

**ただしこの数字はこのfixtureでの値です。** 実buildが高価なほど倍率の影響は大きくなり、逆に起動コストが支配的な今のfixtureでは1.8倍に収まっています。**一般化はできません。**

## 測っていないこと

| 測っていないもの | なぜ重要か |
| --- | --- |
| 内訳（child起動 / 一時ディレクトリ / 検証） | どこを削れるかが分からない |
| 実buildが高価な場合の倍率 | fixtureのchildは即座に終わるので、実際のbuilderでは事情が違う |
| Windows での値 | 本記録は WSL2 のみ |
| 並列実行時の挙動 | state を分けているので並列化できる可能性がある |

**fixtureのchildはほぼ即座に終わります。** 実buildが数秒かかる場合、`-rebuild-check` は「+154ms」ではなく「もう一回分」になります。**倍率はbuild内容に依存します。**

## 検証

- 各条件5回、state と出力先を毎回分離
- 事前に `tei version` を実行してローダのコストを除外
- 測定は `date +%s%N` の前後差
- 使用した script は `.tmp-time.sh`（作業後に削除）

## 限界

- **1環境・1 fixture の値**です。他のホスト・他のbuilderでは異なります。
- 内訳を分けていないので、**最適化の余地は示せません**。
- 判断（P-1〜P-4 のどれを採るか）は §4.25 のまま未決です。
- G4は `UNQUALIFIED` のまま。
