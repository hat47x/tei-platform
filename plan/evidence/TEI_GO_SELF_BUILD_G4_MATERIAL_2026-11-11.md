# セルフビルドの観測は、G4のどこまで埋めるか（§4.52）

§4.50で`./cmd/tei`の全鎖が通りました。本記録は、**その観測が G4（Target別の縮退・移植資格）のどの項目に触れ、どこに触れていないか**を一対一で対応づけたものです。

**これは G4 の判定ではありません。** 適格性を決めるのは Gate の担当であり、ここは**材料の整理**です。

## G4「単独のネイティブ実行ファイル」行との対応

| G4 が求めるもの | セルフビルド側で言えること | 根拠 |
| --- | --- | --- |
| **入口** | 宣言 → catalog → 計画 → ビルド → Claim が一本に通る。`-child` は引数で PATH から解決しない | §4.50・§4.6 |
| **実際の組込み機能** | ビルドされた `tei` が stage1 として次の stage を起動できる | L3 の記録 |
| **依存閉包** | 計画が名指す 75 source と、ビルドが読むものが**双方向で一致**する | §4.41・§4.46 |
| **実OS上の効果** | `linux/amd64` と `windows/amd64` で同じ計画・同じ artifact | クロスOS記録 |
| **再構築** | 同じ計画から二回ビルドして**同じバイト**。隔離木は計画の source だけ | §4.21・§4.42 |
| **交換・停止手順** | **測っていない** | — |

**「交換・停止手順」が空白**です。設計の不足ではなく、**セルフビルドが配備を行わない**ことの帰結（§4.6の境界）。

## 整理の結論

| G4 の項目 | 状態 |
| --- | --- |
| 入口 | **埋まっている** |
| 組込み機能 | **埋まっている** |
| 依存閉包 | **埋まっている** |
| 実OS上の効果 | **二つのホストで埋まっている**（`darwin`・`arm64` は未観測） |
| 再構築 | **埋まっている** |
| 交換・停止手順 | **空白**（セルフビルドの範囲外） |
| 独立 Consumer での適合 | **空白** |
| サイズ・起動時間・RAM | **空白** |

## 言っていないこと

- **G4 の判定**（Gate の担当であり、本記録は材料の整理にすぎない）
- 空白の三項目を埋める設計（**別の担当・別の観測**が要る）
- `qualified` を `true` にする条件（**受理・Authority の話であり範囲外**）

**「セルフビルドを実現した」と「G4 に合格した」は別です。** `qualified` は `false` のままです。
