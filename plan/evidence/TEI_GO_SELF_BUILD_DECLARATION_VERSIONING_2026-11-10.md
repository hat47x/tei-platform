# 能力宣言に版付けの余地が無いことの実測

[#2831](https://github.com/hat47x/tei-platform/issues/2831) のSB-C0 §7 は「能力宣言の**版付け**（今は互換の約束をしない。必要になった時点で決める）」を未決として残しています。本記録は、**「必要になった時点」に本当に決められるのか**を測ります。

**結論：今の形では決められません。** 版を後から足すこと自体が拒否されます。

## 実測

`tools/reference-build-catalog-authoring` に三つの宣言を渡した。

| 入力 | 結果 |
| --- | --- |
| 正しい宣言 | **成功**。catalog 654 バイト、`catalogDigest=sha256:e631efcf…` |
| `"formatVersion": 1` を**トップレベルに足した** | **`declaration: json: unknown field "formatVersion"`、exit 1** |
| `providers[0]` に `"authorityScope"` を足した | **`declaration: json: unknown field "authorityScope"`、exit 1** |

## なぜこうなるか

`Declaration` 型は次で解析される。

```go
decoder.DisallowUnknownFields()
```

**未知のフィールドを拒否する。** そして `formatVersion` は型に存在しない。

したがって **`formatVersion` を足した宣言は、版を名乗ろうとした瞬間に拒否される。** 「版フィールドを導入して互換を管理する」という通常の手段が、**導入時点で使えない**。

## この設計の是非

**「分からない入力を成功として扱わない」という本リポジトリの原則に沿っている。** §4.32 が Workspace と plugin 構文を触らなかった理由と同じ考え方である。

**代償は、宣言形式が「今のキー集合」に固定されることである。** 将来キーを足すと、**古いツールは新しい宣言を読めない**。それは正しい拒否だが、**移行の手段が無い**——版を名指して「これは新しい形式だ」と言う方法が無いため、古いツールは「知らないキーがある」としか言えない。

## 三つの選択肢

| 案 | 内容 | 何が要るか |
| --- | --- | --- |
| **D-1: 何もしない** | 「必要になった時点で」を維持 | 何も要らない。ただしその時点で**破壊的変更**になる |
| D-2: `formatVersion` を今足す | 型に欄を追加し、既定を1にする | 小さな変更。**今足せば、将来の移行で版を名指せる** |
| D-3: 未知キーを警告に落とす | `DisallowUnknownFields` を外す | **原則に反する**。知らない入力を黙って無視することになる |

## 測ったうえでの所見

**D-2 が最も安い。** 理由は三点。

1. **今は誰も宣言を書いていない**（§4.32 が形式を決めていないと明記している）。**互換を壊す相手がいない**
2. **後から足せない**（本記録の実測）。「必要になった時点」は、**既に宣言が存在する時点**であり、そのときは破壊的になる
3. **欄を一つ足すだけ**で、解析の厳格さは保てる

**ただし D-1 を否定しない。** 宣言が**一つも存在せず、今後も外部に出さない**なら、版は要らない。§4.32 は「製品の外のデータ」と決めたが、**外に配るかどうかは決めていない**。

**したがって本記録は判断しない。** 判断に要るのは「宣言を誰に配るか」であり、それは §4.32 が範囲外とした問いである。

## 何を言っていないか

- D-2 を採るべき、とは言っていない。**D-1 が成立する条件（宣言を配らない）を示しただけ**
- 版付けの**中身**（版番号の意味、上げ方）は決めていない
- catalog 側の `formatVersion`（`buildintent.BuildCatalog` は既に `FormatVersion: 1` を持つ）との関係も扱っていない

## 検証

- `go build ./tools/reference-build-catalog-authoring` 成功
- 三つの宣言を実際にツールへ渡し、終了コードと出力を記録
- 成功時は catalog のバイト数と `catalogDigest` を確認
- 拒否時はエラー文言を記録（`json: unknown field "..."`）

**NOT RUN**：宣言を配った場合の旧ツールの挙動（配布経路が無いため）。

## 限界

- 実測は**ツール一つの実装**に対するもので、形式そのものの性質ではない
- `DisallowUnknownFields` を外す変更を試していない（D-3 の実害を測っていない）
- G4は `UNQUALIFIED` のまま。
