# 1つのメッセージから3つの子を同時に起動できる。子からの起動は通らない（2026-11-18、#2515 H6-E2）

- 対象Issue: [#2515](https://github.com/hat47x/tei-platform/issues/2515)の`H6-E2`と`#2509`の経路網羅。機密境界の正本は[TAI #232](https://github.com/hat47x/tai-pleroma/issues/232)。
- 実行日: 2026-11-18（Asia/Tokyo）
- 実行環境: Windows 11 Pro `10.0.26100`（AMD64）、DSH `0.2.2-rc.3`（`dsh --profile headless`）、Node `24.21.0`
- 状態: **ローカルの合成モデルのみ**。実Providerへの接続は**NOT RUN**。
- 先行記録: [`maxDepth 8`の連鎖](../DSH_SUBAGENT_DEPTH8_2026-11-18/README.md)（**1セッション1回**の線形連鎖）。本記録は、そこで残した「**1メッセージで複数の子を同時に起動した場合**」を埋める。

## 1. 何をしたか

**1つのassistantメッセージに`subagent`の`tool_use`を3つ並べて**出させた（**`maxDepth`は既定のまま**）。

## 2. 観測した結果

### 3つとも起動した

| callId | 結果 |
| --- | --- |
| `toolu_1_0` | **`started subagent agent-1`** |
| `toolu_1_1` | **`started subagent agent-2`** |
| `toolu_1_2` | **`started subagent agent-3`** |

- **1つのメッセージから3つの子が起動**した。**セッションは根＋3子＝4**。

### 子からの起動は通らなかった

| 項目 | 値 |
| --- | --- |
| 根からの起動試行 | **1回**（3つの`tool_use`） |
| **子からの起動試行** | **3回**（各子が1回ずつ） |
| **孫セッション** | **0** |
| セッション合計 | **4**（根1＋子3） |

- **子は3つとも起動を試みた**のに、**セッションは増えていない**。
- **孫セッションは0**である。**ただし理由は本記録では特定していない**。**overlayは「上書きなし」**なので**既定値が効いている**が、**その既定値がいくつかは本記録のデータに無い**。**`maxActiveSubagents` が効いた可能性も切り分けていない**。**『拒否された』はセッションが増えないことからの推論**である。

## 3. この記録が示すこと

- **1メッセージで複数の子を同時に起動できる**。**並列の`tool_use`はそのまま通る**。
- **この設定では、子からの起動でセッションは増えなかった**（**孫0**）。**理由（深さ上限か同時数か）は切り分けていない**。
- 機密の観点では、**1回の応答で子を複数立てられる**。**「1メッセージ1子」の前提は置けない**。
- **子の起動試行は静かに失敗する**（**根のstdoutに拒否の文言は出ていない**）。

## 4. この記録が示さないこと

- **拒否の文言そのもの**。**根のstdoutには出ていない**ので、**「拒否された」はセッションが増えないことからの推論**である。
- **`maxActiveSubagents` が同時に効いたか**。**本記録では切り分けていない**。
- **`maxDepth` を上げた状態で複数同時に起動した場合**（本記録は**既定**）。
- **子がさらに複数を同時に起動しようとした場合**。
- **並列数の上限**（3で試しただけ）。
- **時間・リソース**、実Provider、サーバー側の保存。
- `H6-E2`の合否、機密Profile適合、Owner受理、#1119のGate。

## 5. 生データ

| ファイル | 内容 |
| --- | --- |
| `multi-spawn.json` | `overlay`（既定）、`childrenPerMessage`、`sessionsObserved`・`rootSession`・`childSessions`、`requests`（11件のbytes・SHA-256・sessionId・**role**・`willMultiSpawn`・`childrenPerMessage`）、`spawnAttempts`（**根1・子3**）、`grandchildrenCreated`、`sessionAccounting`（**根1・子3・孫0**）、`answers`、`sessionsVsAttempts`、`caveat` |

生の要求bodyはコミットしていない。**合成のみ**（`MULTI_CANARY_77n`）。

再現する場合の要点:

- **1つのassistantメッセージに`tool_use`を複数並べる**（`content_block_start`をindex違いで複数）。
- **子には「起動するな」と指示しても、Mockは機械的に起動を試みる**。**試行回数と生成セッション数を分けて数える**。
- **セッションIDで束ねる**。要求番号だけでは**どのセッションか分からない**。

### 手法上の注意（実際に踏んだ）

**子も起動を試みる**ため、**「起動試行＝セッション生成」と数えると過大になる**。**本記録では試行4回に対しセッション4（根1＋子3）**で、**子の試行3回は0セッション**だった。**試行と生成を別々に集計する**必要がある。

## 6. `H6-E2`への含意（判断はしない）

**1メッセージで複数の子を立てられる**ので、**「1回の応答で増えるセッション数」を1と見積もれない**。**既定の設定では子からは広がらない**が、**`maxDepth` を上げれば広がり得る**。どの統制を採るかは#2515とTAI #232のOwner判断であり、本記録は判定しない。
