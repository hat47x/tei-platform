# タイムアウト後に届いた遅延応答はモデルの入力に現れない（2026-11-17、#2515 H6-E2）

- 対象Issue: [#2515](https://github.com/hat47x/tei-platform/issues/2515)の`H6-E2`と`#2509`の経路網羅。機密境界の正本は[TAI #232](https://github.com/hat47x/tai-pleroma/issues/232)。
- 実行日: 2026-11-17（Asia/Tokyo）
- 実行環境: Windows 11 Pro `10.0.26100`（AMD64）、DSH `0.2.2-rc.3`（`dsh --profile headless`）、Node `24.21.0`
- 状態: **ローカルの合成MCPサーバーのみ**。実MCPサーバーへの接続は**NOT RUN**。
- 先行記録: [stdioの応答待ち](../DSH_MCP_STDIO_TIMEOUT_2026-11-17/README.md)（タイムアウトで子は殺されない）。本記録は、そこで未確認とした「**遅れて届いた応答が使われるか**」を埋める。

## 1. 何をしたか

**`toolCallTimeoutMs: 2000`** に対して、子は**6秒眠ってから応答を書く**。その応答に**合成のcanary（`LATE_REPLY_CANARY_313`）**を入れた。

**実行を遅延応答より長く生かす**ため、**モデル側の2回目以降の応答を12秒遅らせた**（追加のToolを呼ばせるとリクエストが挟まって当てにならないため、**モデル自身を遅くする**方を選んだ）。

## 2. 観測した結果

### 子は遅延応答を書いたが、モデルには届かなかった

| 項目 | 結果 |
| --- | --- |
| 子が遅延応答を書いたか | **書いた**（`late-reply-sent` t=6.25） |
| **canaryがモデル要求に現れたか** | **現れない**（3件すべて） |
| 呼び出しの結果 | **`Error: Request timed out`** |
| クライアントのキャンセル | **送られた**（`notifications/cancelled`） |
| 実行の終了コード | 0 |

- **モデル要求は3件**（`responseDelayed` が12秒のものが2件）。**実行は遅延応答の到着後も続いている**。
- それでも**canaryはどの要求にも入っていない**。**遅延応答はモデルの入力に現れない**。**破棄を記録したログは無い**ので、**「捨てられた」は観測からの推論**である（観測できたのは**入力に無いこと**だけ）。

### キャンセルは「応答が来てから」送られる

```
tools/call  t=0.25
sleeping    t=0.25
late-reply-sent  t=6.25   ← 子が応答を書く
notifications/cancelled t=6.25 ← その直後にキャンセル
```

- **キャンセルは子の応答を契機に送られている**。つまり**`notifications/cancelled` は「子を止める」手段として先回りしない**。
- **`honour`モード（キャンセルを尊重する子）でも順序は同じ**だった。**キャンセルが届いた時点で既に応答を書いている**ので、**尊重しても遅延応答は抑えられない**。

## 3. この記録が示すこと

- **タイムアウト後の応答はモデルの入力に現れない**（**破棄の機構そのものは未観測**）。
- **キャンセルは「呼び出しを諦めた」ことを伝えるが、応答の生成を止めない**（**止めるのは子の実装次第**で、**タイミングも間に合わない**）。
- 機密の観点では、**外部Effectを持つToolがタイムアウトした場合、Effectは実行済みかもしれない**が、**その結果はモデルに戻らない**。**「結果が無い＝何も起きていない」ではない**（**子は応答を書いている**ため。ただし**外部Effectの実体は本記録では測っていない**）。

## 4. この記録が示さないこと

- **他のtimeout／sleepの組み合わせ**（本記録は2000ms＋6秒睡眠の1組）。
- **モデル側を遅らせずに実行を生かす方法**での同じ観測。
- **遅延応答が別の呼び出し（同じcallId）で再利用されるか**。
- **http経路での遅延応答**。
- **キャンセルを送る条件そのもの**（何を契機に送るかは、この1例からは「応答の到着」としか言えない）。
- 実MCPサーバー、サーバー側の保存。
- `H6-E2`の合否、機密Profile適合、Owner受理、#1119のGate。

## 5. 生データ

| ファイル | 内容 |
| --- | --- |
| `stdio-late-reply.json` | `overlay`（timeout・睡眠・モデル遅延）、`lateReplyCanary`、`runChildIgnoresCancel`／`runChildHonoursCancel`（子側の全ログと各イベントの時刻）、`modelRequests`（3件のbytes・SHA-256・Tool数・遅延秒・**canary含有判定**）、`canaryReachedModel`、`toolResultText`、`answers`、`caveat` |

生の要求bodyはコミットしていない。**合成のみ**（`cancelmock`・`slow_echo`・`LATE_REPLY_CANARY_313`）。

再現する場合の要点:

```yaml
- insert:
    - id: mcp-client-cancel
      name: "@deepseek-ai/dsh-mcp-client"
      config:
        transport: stdio
        serverName: cancelmock
        command: python
        args: ["<script>", "<record-dir>", "6", "ignore"]
        toolCallTimeoutMs: 2000
        failOnStartupError: false
```

- **実行を遅延応答より長く生かす**必要がある。**モデルの応答を遅らせる**のが確実だった。
- **追加のToolを呼ばせて稼ぐ方法は失敗した**。DSHが**Tool一覧の無い要求を挟む**ため、狙った順序にならなかった。
- 判定は**モデル要求のbodyにcanaryがあるか**で行う。**子が書いたこと**と**届いたこと**は別。

## 6. `H6-E2`への含意（判断はしない）

**遅延応答はモデルの入力に現れない**。したがって**タイムアウトした呼び出しの結果は、後からモデルへ戻らない**（**この1例・このtool・このtimingで**）。外部Effectを持つToolでは、**「タイムアウト＝結果不明」**として扱う必要がある。どの統制を採るかは#2515とTAI #232のOwner判断であり、本記録は判定しない。
