# `maxDepth 8`でも深さ8まで伸び、9段目が`subagent depth 9 exceeds maxDepth 8`で止まる（2026-11-18、#2515 H6-E2）

- 対象Issue: [#2515](https://github.com/hat47x/tei-platform/issues/2515)の`H6-E2`と`#2509`の経路網羅。機密境界の正本は[TAI #232](https://github.com/hat47x/tai-pleroma/issues/232)。
- 実行日: 2026-11-18（Asia/Tokyo）
- 実行環境: Windows 11 Pro `10.0.26100`（AMD64）、DSH `0.2.2-rc.3`（`dsh --profile headless`）、Node `24.21.0`
- 状態: **ローカルの合成モデルのみ**。実Providerへの接続は**NOT RUN**。
- 先行記録: [`maxDepth 7`の連鎖](../DSH_SUBAGENT_DEPTH7_2026-11-18/README.md)（深さ7まで）。本記録は、そこで未確定とした「**`maxDepth 8` 以上**」の**`8`**を埋める。

## 1. 何をしたか

`subagent`の**既存エントリ`id`に`config`を上書き**して**`maxDepth: 8`**にした。**Mockは「1セッションにつき1回だけ起動する」ように作った**（**これは実験の作り方であって、「2回目以降が起きない」という観測ではない**）。

## 2. 観測した結果

### 9セッション、深さ0〜8

| 深さ | Session | 最初の要求 |
| --- | --- | --- |
| **0**（根） | `session-…` | `001-request.json` |
| 1〜7 | （各1セッション） | `004`〜`017` |
| **8** | （1セッション） | `019-request.json` |

- **要求は合計20件**。**起動の試行は9回、成功8回、拒否1回**。
- **`maxDepth 7`では8セッション**だったので、**設定値どおり1段伸びた**。

### 拒否の文言

深さ8のセッション（**1つだけ**）がさらにもう1回起動しようとした結果（`020-request.json`）:

```
Error: subagent depth 9 exceeds maxDepth 8
```

- **試みた深さ（9）と上限（8）の両方**が本文に現れる。
- **拒否されたセッションは深さ8**で、**10セッション目はできない**。

## 3. この記録が示すこと

- **`maxDepth 8` は深さ8まで通す**。**9段目は拒否**される。
- **8でプラグイン固有の頭打ちは現れなかった**。**設定値がそのまま上限として効いている**。
- **本記録が測ったのは `8` の1点**である。**3〜7 は別記録の値**（下の比較表）。
- **6点（3〜8）を並べると、設定値どおりに1段ずつ伸びている**。**上限としての効き方は8まで一貫**している。

### 深さの求め方（解釈であること）

生データに**明示的な親子リンクは無い**。深さは**セッションIDの初出順**と**各セッションが1回だけ起動した事実**から求めた**解釈**である。**線形の連鎖では正しい**が、**分岐すると順序だけでは決まらない**。

### 起動の要求と拒否の文言が載るファイルは別

**深さ8のセッションでは、起動を試みた要求が`019`、拒否の文言が`020`** に分かれている。**`019`は`willSpawn: true`の9回目の試行**であり、**拒否の文言はその次の要求`020`** （tool結果がモデルへ戻される要求）に現れる。**1要求ぶん離れているのは自然な並び**である。

## 4. この記録が示さないこと

- **`maxDepth 9` 以上**と**プラグイン固有の頭打ちがあるか**。**8点では見えていないが、上限が無いとは言えない**。
- **1メッセージで複数の子を同時に起動した場合**（本記録は**1セッション1回**）。
- **`maxActiveSubagents` との同時作用**（別記録で深さ3・同時2は確認済み）。
- **`subagent_fork` の連鎖**、**実Providerの動作**。
- **時間・リソースの消費**。**本記録に所要時間の記録は無い**（実行全体が約3.9秒だったのは**外側のシェルの観測**で、**DSHの起動も含む**。**セッションごとの時間ではない**ので、そうは報告しない）。
- `H6-E2`の合否、機密Profile適合、Owner受理、#1119のGate。

| ファイル | 内容 |

| `depth8.json` | `overlay`（`maxDepth: 8`）、`configuredMaxDepth`、`sessionsObserved`・`maxDepthReached`、`depthBySession`、`rootSession`、`requests`（20件のbytes・SHA-256・sessionId・深さ・Tool数）、`refusalText`・`refusalFile`・`refusalSession`・`refusalSessionDepth`・`refusalAttemptedDepth`・`refusalLimit`、`spawnAccounting`（**試行9・成功8・拒否1**）、`internalCapObserved`、`comparison`（3〜8の6点）、`caveat` |

再現する場合の要点:

```yaml
- id: subagent
  config:
    maxDepth: 8
```

- **既存エントリの`id`に`config`を上書きする**。`insert`で足すと**有効化に失敗**する（先行記録で踏んだ）。
- **Mockを1セッション1回に固定する**。**そうしないと深さが伸びない**。
- **深さは到着順で求める**（**線形の連鎖でのみ正しい**）。

## 6. `H6-E2`への含意（判断はしない）

`maxDepth` は**8でも設定値どおりに効く**。**3〜8の6点で一貫**しているので、**委任の深さを制限する統制として8段までは期待できる**。ただし**9以上と、プラグイン固有の上限は未確認**である。どの統制を採るかは#2515とTAI #232のOwner判断であり、本記録は判定しない。
