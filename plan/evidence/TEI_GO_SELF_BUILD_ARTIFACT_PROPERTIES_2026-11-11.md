# G4が求める物性値を測る（§4.54）

§4.52 は「サイズ・起動時間・RAM」を**空白**として残しました。本記録は、**それを測った**結果です。

**これは G4 の判定ではありません。** G4 がこれらの値を求める以上、**測っておく**。合否の基準は Gate の担当です。

## 測ったもの

`./cmd/tei` を、計画経路と同じ呼び方（`go build -trimpath -buildvcs=false`）でビルドしました。対象 commit は `6057593bd`。

| 項目 | 値 |
| --- | --- |
| **サイズ** | **29,028,974 bytes（27.68 MiB）** |
| **起動時間**（`tei version` が答えを返すまで） | **中央値7.9 ms**（5回: 7.9 / 7.3 / 15.0 / 7.6 / 14.5） |
| **ピークRSS**（`tei version` 実行中） | **12,452 KiB（約12.2 MiB）** |
| **再構築** | 二回のビルドが**バイト一致**（`sha256:6918fdea…`） |

## 数値の読み方

**起動時間のばらつき（7.3〜15.0 ms）は測定環境の負荷**です。中央値を採りました。**「7.9 ms で起動する」は、5回のうち3回が7〜8 ms 台だったという意味**であり、**上限を主張しません**。

**RSS は `tei version` を答えるだけの値**です。実際の作業（ビルド・検証）ではもっと大きくなります。**G4 の「RAM」がどの操作を指すかは決まっていない**ので、ここでは**最小の操作**を測ったと明記します。

- 重い操作（`self-build`・`validate` 全体）での RSS・時間
