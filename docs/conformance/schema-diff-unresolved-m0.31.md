# M0.31 構造差分で比較未確定を扱う準拠確認

## 目的

M0.31では、構造差分の比較において、「構造の違いを確認できた状態」と「比較に必要な表記統一の情報が足りない状態」を区別できるようにします。

対象はIssue #60です。まず、提供元固有の式を表すProviderExpressionの表記の違いを扱います。

## 背景

高度な索引では、式を使うキーと部分索引の条件式を`ProviderExpression`として保持します。期待する側には人が記述した文字列が、PostgreSQLの実際の状態には管理情報から復元された文字列が入ります。そのため、同じ提供元とSQLの方言でも、意味が同じ式の表記が一致するとは限りません。

文字列の違いだけで直ちに`drop-index`と`add-index`を返すと、意味上は同じ索引を不要に作り直す可能性があります。

一方、表記が違う式を常に同じ意味だと判断することもできません。提供元固有の式について信頼できる表記統一の手順がない場合は、一致・不一致のどちらとも確定できない状態として返します。

## 差分結果の二種類

`schemadiff.Diff`は、次の二種類を分けて保持します。

```text
Diff
  Database
  Changes[]
  Unresolved[]
```

`Changes`には、構造の違い、または実際の構成要素の利用状態の違いとして確定した項目を記録します。

`Unresolved`には、提供元固有の表記統一などの追加情報が必要で、現時点では構造の違いを安全に断定できない項目を記録します。

`Unresolved`を`ChangeKind`には含めません。比較結果が未確定であることは、移行操作を意味しないためです。

## 提供元固有の式に関する初期規則

同じ名前の索引を比較するとき、提供元固有の式について次の規則を適用します。

1. 両方がnilであれば一致とする
2. 片方だけがnilであれば構造差分とする
3. 提供元またはSQLの方言が異なれば構造差分とする
4. 提供元・SQLの方言・元の式の文字列がすべて同じなら一致とする
5. 提供元とSQLの方言は同じで、元の式の文字列だけが異なる場合は比較未確定とする

5番目の場合、中核部分ではSQL式の意味が同じかどうかを推測しません。

## 索引全体の判定

提供元固有の式を比較できなくても、追加の格納列、キーの数、列、照合順序、演算子クラス、並べ替え、NULLの順序、一意性、索引方式などに明らかな違いがあれば、索引全体として構造差分を確定できます。

その場合は従来どおり`drop-index`と`add-index`を返し、同じ索引について提供元固有の式の`Unresolved`を重複して記録しません。

明確な構造差分がなく、提供元固有の式だけを比較できない場合は、`drop-index`や`add-index`を返さず、`Unresolved`だけを返します。

## 状態遷移

実際の索引の`valid / ready / live`は比較が未確定な情報ではなく、観測によって確認した状態です。

そのため、構造の比較が未確定でも、実際の索引を利用できない状態なら、`index-state-drift`を従来どおり確定した変更項目として返せます。

## 項目への経路

初期実装では、比較が未確定となった箇所を次のような項目のパスで示します。

```text
index.keys[0].expression
index.predicate
```

配列の位置は、物理構造内の先頭を0として数えます。

## 移行処理との境界

`migration.Render`は、`Diff.Unresolved`が1件でも残っている場合、その差分からSQLを生成しません。

M0.31では、確定した変更だけを部分的に実行することもしません。一つの差分に比較未確定の項目が残るまま移行計画を作ると、適用後にどの状態へ収束するかをTEIが説明できなくなるためです。

将来、構成要素ごとに安全に分離して一部だけ適用する必要が生じた場合は、別途設計します。

## 非目標

- 提供元固有の式の意味をそろえる処理そのもの（Issue #54）
- 提供元へ接続しない場合の方針の実装（Issue #59）
- 照合順序や演算子クラスなどの一般的な表記統一（Issue #58）
- 高度な索引のDDL生成（Issue #55）
- SQL構文木による式の同値性判定

## 完了条件

- 提供元とSQLの方言が同じでも元の式が異なれば`Unresolved`になる
- その場合に`drop-index`と`add-index`を返さない
- 提供元やSQLの方言の違い、nilの有無は従来どおり構造差分とする
- 提供元固有の式以外に明確な構造差分があれば、通常の索引の変更として扱う
- 実際の索引の利用状態の違いを見落とさない
- `migration.Render`が比較未確定を含む差分を拒否する
- 既存の確定済みの差分の出力を維持する
