# TEI仕様書テンプレート

[仕様書の共通様式](../specification-style.md)を新しい設計文書で使うための、**任意のひな形**です。これらは記入欄を示す説明用Markdownであり、TEIの型付きSource（`*.tei.md`）や製品契約の正本ではありません。

| テンプレート | 想定対象 | 開始点 |
| --- | --- | --- |
| [機能仕様](feature-spec.md) | 利用者の操作、業務機能、画面・編集の振る舞い | 一つの利用場面・失敗例 |
| [契約仕様](contract-spec.md) | DSL、データ型、プラグイン、API、変換・外部参照 | 一つの入出力・例外 |
| [構成仕様](architecture-spec.md) | サブシステム、実行経路、Target・Providerの責務 | 一つのシナリオと境界 |

## 使い方

1. 対象に近い一つをコピーし、用途に不要な章は削る。複数を無条件で結合しない。
2. 記入例やプレースホルダーを置換し、対象範囲・状態・参照する正本を先頭に示す。
3. 採用前の設計は原則`plan/design/`、現行実装に対応した説明は`docs/`へ配置する。要求の正本は`requirements/`、判断は`plan/adr/`へ置く。
4. 既存の契約・モデルを転記して二重管理せず、安定した識別子・リンク・対象版で参照する。
5. 試験結果は、手順・対象版・Expected・Actualを混同せず、実際の証拠へリンクする。

小さな仕様書では冒頭・使用例・契約・検証の4節だけでも構いません。章を埋めたかどうかより、読者が必要な判断と検証へ辿れることを優先します。

文書の自然な日本語や説明順序は[文書品質ガイド](../documentation-quality.md)、正本の配置は[文書案内](../README.md)に従います。Markdown内の表・DSL・テストを意味として解釈する仕組みは[Issue #2621](https://github.com/hat47x/tei-platform/issues/2621)の担当であり、本テンプレートのコピーだけでは有効になりません。
