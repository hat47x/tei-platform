TEI 想定仕様ガイド

X-TEA／XEADから得た設計上の示唆

X-TEA／XEADの公開資料と参照可能なモデルを、TEIの設計要件を検討するための外部参照の一つとして照合しました。

位置づけ

TEIはX-TEA／XEADの公式な後継・派生プロジェクトではありません。本ページは、公開資料等から確認できる設計上の考え方を独立に調査し、TEIの要求と照合した記録です。差異は優劣ではなく、想定する用途・技術環境・責務境界の違いとして扱います。

参照対象の実装やモデルをTEIの互換要件として再現することは目的としません。また、参照モデルの内容そのものは、利用条件を確認できない状態で複製・再配布しません。

確認できた重要な示唆

観点参照資料から得た示唆TEIでの扱い
Data / Function / Business一つの業務システムを複数の視点から照合し、単一視点では見落とす不足や矛盾を検討できる。三視点を同一のsource of truthへ潰さず、相互参照できるProjectionとして扱う。
Business Action業務行為にはシステム機能だけでなく、手作業・対話・物理的な受渡し等も含まれ得る。Business ActionとApplication Functionを同一視せず、manual / external / unresolvedも表現可能にする。
Function / IO機能、画面・帳票、データ入出力、機能間の利用関係を横断して確認できる。API一覧や画面階層だけに縮約せず、InteractionとDataへの関係を追跡する。
Subsystem外部データへの操作や外部機能利用を見ながら、凝集・結合の境界を検討する。namespaceやdeployment単位だけで境界を決めず、実際の依存関係をEvidenceとして確認する。
実行による検証設計内容を動かして確かめることで、設計と実現のずれを見つけられる。TEIではSemantic / Realization / Runtime / Evidenceの責務を分けたうえで、Referenceを通じて検証する。

TEIでそのまま前提にしないもの

参照資料に見られる具体的なXML構造、画面構成、クラス構造、実行方式は、そのままTEIの仕様にはしません。TEIでは複数Target、Provider分離、明示的なauthority、Observation / Evidence、file-native authoring等の現在の要件から責務境界を決めます。

同様に、参照資料に特定の表現があることだけを理由に、未決のTEI仕様を確定しません。実際の業務ScenarioとReference Evidenceで必要性を確認します。

静的照合で確認した範囲

参照可能なModeler／Driver資料および複数のリファレンスモデルについて、構造・関係・代表的な業務記述を静的に照合しました。たとえば、一つのBusiness Actionが複数のFunction / IOを利用する例や、Function参照を持たずに成立する業務行為が確認でき、TEIでBusiness Actionを単一のApplication Patternへ固定しない判断を支えています。

この確認は、すべての画面・実装・実行経路を網羅した製品評価ではありません。実行時の完全な意味互換、性能、品質、保守性等を本ページから推定しません。

参照と再現性

公開原典と、TEI側で採用した設計判断の追跡先は資料・出典と仕様の追跡にまとめます。機械的な静的集計値はxtea-observations.jsonに分離し、本文では必要な含意だけを記述します。
