TEI 想定仕様ガイド

資料・出典と仕様の追跡

外部公開に必要な範囲で、TEIの想定仕様が何を根拠にしているか、どこで採用状態を確認できるかを整理します。

追跡の原則

TEIでは、現在のProduct Requirements、採用済みArchitecture / ADR、実装とEvidenceを、過去の構想や検討記録より優先します。未統合案や研究上の仮説は、採用済み仕様と区別して扱います。

このページは調査作業そのものの履歴ではなく、第三者が仕様の根拠を追うための入口です。個々のチャット、作業用ファイル、ローカルな取得手順など、仕様理解に不要な内部過程は掲載しません。

TEI内の主要な正本

種類主な参照先役割
ProductValue / Vision / Principles何を価値とし、何を目指すか。
RequirementsTEI Product Requirements満たすべき要求。
ArchitectureArchitecture / Business System Design責務境界と意味上の制約。
Planning / EvidenceMaster Plan / Acceptance Scenario Traceability能力到達点、受入条件、未解決事項。
Implementationtei-platform Repository実装とテストによる現在の実証状態。

外部の設計参照

TEIの設計検討では、業務システム設計、モデル駆動・メタデータ駆動設計、実行可能仕様、複数Target、AI支援authoring等の公開知見を参照します。参照はTEIの公式な系譜や互換性を意味しません。

出典参照する観点
渡辺幸三：データ、UI、業務手順の「3要素」をとらえるData / Function / Businessを複数視点から捉える業務システム設計。
渡辺幸三：蔓延する「ブルシットエンジニアリング」構造化された業務・機能・データ定義の関係。
XeadModeler / XeadDriver設計内容を具体的な表現・実行へつなぐ際の参照。

X-TEA／XEADに関するTEI側の整理はX-TEA／XEADから得た設計上の示唆を参照してください。

引用・再利用の扱い

外部資料からは、公開範囲で確認できる事実・設計上の考え方を参照します。第三者のモデルや文書の内容を、利用条件が確認できない状態でTEI Repositoryへ複製・再配布しません。必要な検証結果は、可能な限りTEI自身のReferenceや独立した要約・集計として残します。

仕様の状態

この仕様ガイドには、採用済みの境界だけでなく、評価待ちの候補も含まれます。各ページでは、未決事項を完成済みの能力として読めないよう区別します。最終的な現在地はRepositoryの要求・ADR・実装・Evidenceを優先してください。
