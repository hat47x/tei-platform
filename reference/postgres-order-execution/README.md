# PostgreSQL上の受注操作とサービス契約

`order_entry`の受注と明細を、使い捨てのPostgreSQL 16で読み取り、業務検証と認可を経て確定し、別の読取りで状態を観測する参照例である。プラグイン基盤の選択済み呼出しを使う。顧客参照と認証は既存の模擬実装を残し、応答の`evidenceSources`に実DB部分と模擬部分を明示する。

## 再現

Go、Python 3、Dockerが使えるLinux環境で、変更のない候補版から実行する。

```sh
python3 tools/verify-postgres-order-execution.py --output /absolute/path/outside-repository
```

検証器は自分で作ったコンテナーだけを対象とし、`fixture.sql`で空の専用DBへ参照データを作る。既存オブジェクトを削除しない。実行後はコンテナーと一時接続ファイルを削除する。出力先はリポジトリ外に限定し、候補版・実行物のSHA-256・各確認項目・実行前後の変更状態・後片付けの確認を`evidence.json`へ残す。

この参照例は、実際のPostgreSQLエンジンを使った合成業務データの検証である。本番のデータ、Oracle接続、実際の認証提供元、人による操作、表示品質、可用性の根拠にはしない。

構築時にWorldを固定した受注専用JSON APIも、同じDBアダプターへ接続できる。次の指定で、既存の固定World構築手順による実行物に対し、同じ実DB試験とHTTP・独立SQL照合を実施する。

```sh
python3 tools/verify-postgres-order-execution.py --frozen-api --output /absolute/new/frozen-postgres-evidence
```

固定Worldの指紋と構築版Tは実行物に結び付け、DBの実行許可はその実行物のSHA-256へ設定する。固定Worldではライブソースの版指定を受け付けず、DB許可の`model_revision`は空文字を使う。`--source-loop`はこの検証と併用できない。`--non-screen`を追加すると、同じ固定Worldの実行物から帳票と一括処理も検証する。接続設定の不足や選択済みサービスの未指定を起動前に拒否する。修理受付専用ビルドではPostgreSQL引数自体を受け付けない。

## 実装と安全条件

ウェブ参照実装の`-composition-scenarios -postgres-dsn-file /secure/connection-file -postgres-fencing-token 1`で接続する。ホストは接続ファイルを読み、SQLを実行する。サーバー自身は表・許可・参照データを作成しない。接続エラーに接続文字列を複製せず、失敗時に模擬データへ戻らない。

読取は受注・明細・物理的な行版を一つの反復可能読取りで取得する。物理的な行版は`storageRevision`として追跡し、業務上の識別子にしない。確定処理は行版・現在の状態・検証済み明細の一致を再確認し、現在の業務認可を再取得する。確定済みの受注や同じ古い版に対する競合は拒否する。

実行許可はホストが所有する`tei_reference_execution_grants`に置き、契約、提供元、実際の実行物、世代、有効期限、排他トークンを照合する。この表は参照ホストの実行権限であり、製品の新しい汎用認可モデルではない。業務意味や資格情報も保存しない。

確定処理は許可行の共有ロックを取得してから更新し、同じ行への失効・排他トークン更新と直列化する。期限は更新直前にも検査する。通信を含む確定の失敗は結果不明とし、自動再試行しない。更新直前の期限検査は応答時刻までの有効性を保証しない。

明細の再検査から確定まで、挿入・変更・削除を防ぐため表全体を共有ロックする。小さな参照例の安全性を確かめるための選択であり、本番の並行性能や汎用の状態移行には未適用である。実行物のハッシュ一致も、配布元の署名や提供元の適合証明ではない。

通常の全体検証では実DB専用試験を省略する。省略を実DBでの合格と扱わず、上記検証器が`TEI_REFERENCE_POSTGRES_TEST_DSN_FILE`を設定し、実DB試験が一件も省略されなかったことを確認する。試験がデータを変更する前には、各表にこの参照例の所有標識があることを検査する。

段階計画は[機能拡充と基盤の接続](../../plan/workstreams/REFERENCE_MODEL_PLUGIN_EXECUTION_2026-10.md)、実行入口は[ウェブ参照実装](../../tools/reference-first-web-target/README.md)を参照する。

`--source-loop`を付けると、同じ使い捨てDBに[ソース変更の受理から再実行まで](../source-execution-loop/README.md)の確認を追加する。ホストがソース版を選ぶ場合は、実行許可の`model_revision`もその版に合わせる。版を選ばない通常の参照ホストには空文字の許可を使い、版に結び付いた許可を流用しない。
