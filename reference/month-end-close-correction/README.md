# 月次締めと、締め後に届く訂正の計上(`month-end-close-correction`)

締めの担当者と運用者が、営業日カレンダーの確定、締め時刻のファイル取込み、締めジョブの実行、締め後の遅延到着の受付、遡及の改定と赤黒の訂正、端数処理と締め時点の帳票の再出力までを、一回の月次締めとして行う技術検証用サンプルです。確かめたいのは、オンラインの更新を止めずに締めの時点が一つに決まり、二重起動や担当サーバの交代を挟んでも締めの結果が明細と一致し、締め後の訂正が締め済みの値を変えずに計上されるか、という点です。

- 状態: 設計案は提案段階で、このサンプルは新設です。工程を担う既存資産はなく、このREADMEは工程と失敗注入の計画だけを示します。全工程の現状は「足場なし」です。
- 設計の正本: [技術検証用サンプルの統合設計 4.11節](../../plan/design/TECH_VALIDATION_SAMPLES_2026-10.md#411-月次締めと締め後に届く訂正の計上month-end-close-correction新設)。技術検証用サンプルの位置づけ、物語、受け渡しの詳細はそちらを参照してください。
- 複合シナリオC2とC4は、このサンプルの通しの検証として行います([3.3節](../../plan/design/TECH_VALIDATION_SAMPLES_2026-10.md#33-複合シナリオの対応))。C4は、4の会員向けの経路と5の承認途中の案件ができてから加えます。

## 通しの完了条件

現在、通しの完了条件はどれも成立していません。工程も通しの検証もまだありません。

- 工程1で確定したカレンダーの版と締め日が、取込み、締め、訂正、帳票まで同じ値で引き継がれる。途中でカレンダーを読み直すと、版の不一致として止まる。
- 締めの対象の時点が一つに決まり、オンラインの更新、二重起動、担当サーバの交代を挟んでも、締めの結果と明細の合計が一致する。
- 締め後の訂正と遡及の改定は、締め済みの期間を書き換えず、元伝票と結んだ赤黒の伝票として計上される。締め時点の帳票を締め時点の記録で再出力すると、締めた金額と一致する。
- 税額は、どの計算経路でも同じ値になる。
- 合成のファイル、模擬のメッセージ、同じ機械の上のサーバで確かめた結果を、実際の取引先との連携や本番の締めが成立した証拠にしない。

## 基盤への改善圧力

見出しだけを示します。現状、求める条件、確認方法は、4.11節の「基盤への改善圧力と現状」を参照してください。

- P-TIME-05: 版つきの暦と、改訂の影響の特定(データ)
- P-INT-01、P-INT-02: ファイル仕様の宣言と、取込み単位の冪等性(プラグイン)
- P-JOB-01: ジョブの実行を業務キーで識別し、再開と二重起動を制御する(実行時)
- P-OPS-01: 担当サーバの交代と排他トークンの永続化(実行時)
- P-TIME-01、P-TIME-02: 業務日付、期間の状態、確定した行の不変性と赤黒の訂正(コア)
- P-TIME-03: 有効時間と記録時間の二つの軸での照会(データ)
- P-TIME-04: 順序の鍵、版、遅延到着の方針(実行時)
- P-CALC-01: 端数処理の単位と方式の宣言(データ)
- P-B2C-02: 締めジョブと会員向けの照会の資源の分離(実行時)
