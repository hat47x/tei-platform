# 多言語表示資源の参照実装（E1）

このディレクトリは、[課題 #1396](https://github.com/hat47x/tei-platform/issues/1396)の設計を小さく検証するための**読み取り専用の参照実装**です。製品用の翻訳管理機構や正式なプラグインではありません。

背景と実装候補の全体像は[多言語対応の設計案](../../plan/design/MULTILINGUAL_SEMANTIC_RESOURCE_DESIGN_2026-10.md)に記載しています。

## 今回確認すること

受注アプリケーションの意味上の識別子 `sales.order.submit` を例に、表示文字列を日本語と英語で切り替えます。これは、参照用作業領域の[受注定義](../workspace/semantic/sales/order.tei)にある機能名です。試験では、既存の `modelref.Key` を使った**試験用のグラフ**を構築しており、受理済みモデルを読み込んだ証拠ではありません。

[`testdata/order-entry.json`](testdata/order-entry.json)には、日本語の原文、確認済みの英語訳、原文の旧版に基づくフランス語訳を記録しています。`fixture_test.go`はこのデータを読み、正常な表示と言語資源の失効を検査します。試験用の表示資源を正式なアプリケーション設定へ導入するものではありません。

表示資源には、所有者、意味参照、表示上の役割、原文の言語と版、翻訳文、参照した原文の版、確認状態を含めます。翻訳を取得しても、意味上の識別子と業務規則は変更しません。

読み取り時には、次の境界を検査します。

- 意味参照が存在しない場合と、表示資源自体が存在しない場合を区別する。
- 同じ資源や言語の重複を登録順で解決せず、構造化した診断で拒否する。
- 明示的な代替言語を除き、似た言語タグへの暗黙の切替を行わない。
- 原文の版が異なる翻訳や、確認されていない翻訳を表示しない。別の代替訳へ黙って切り替えることもない。
- 重要文言については、要求言語と一致しない翻訳や原文への代替を許さない。
- `golang.org/x/text/language`で言語タグを解析し、正規化済みの表記を要求する。これはTEIの言語設定全体の実装を意味しない。

## 検証方法

リポジトリのルートから、関連する試験だけを実行します。

```bash
go test -count=1 ./reference/multilingual-resources
go test -race -count=10 ./reference/multilingual-resources
go vet ./reference/multilingual-resources
gofmt -l reference/multilingual-resources/*.go
```

試験で使うグラフと表示資源は合成した固定データです。実際の受注画面、帳票、配布成果物、外部の翻訳サービスを検証したものではありません。

## 既存機構に残す責務

この実装は言語資源の候補を読み取り、指定された言語の表示文字列を返すだけです。次の機能は実装しません。

- プラグインやその実装の選択、依存解決、固定情報の発行。
- 意味モデルの受理や、正式なデータモデルからの参照グラフ生成。
- 利用者・組織・環境の言語設定の優先順位の決定。
- MessageFormat 2の構文解析、引数の型検査、数値・日時書式、文章方向の表示。
- 生成AI翻訳、訳文の承認操作、権限管理、ビルド時の資源抽出。
- 翻訳資源の保存方法や新たな設定形式の確定。

実装候補から製品機能へ進める前に、少なくとも既存のプラグイン契約（#951）、構築・成果物管理（#943）、三視点参照（#1120）との接続を確認します。参照実装を動かせたことだけでは、多言語対応の完成や本番利用可能性を証明できません。
