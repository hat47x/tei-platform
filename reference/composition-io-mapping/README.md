# 項目の入出力対応を調べる参照実装

状態：[#1223](https://github.com/hat47x/tei-platform/issues/1223)に属する独立した設計用の試作。[入出力対応の方式設計候補](../../plan/design/PLUGIN_DEPENDENCY_IO_MAPPING_DESIGN_2026-10.md)のE2を進めるためのもので、製品の読み込み形式、型体系、実行時の接続方式は確定しない。

## 確かめること

`Inspect`は、利用側の局所名と項目付きの契約を受け取り、対応付けの不足、型と多重度の不整合、出力から入力へのデータ順序を診断する。提供元の選択は、既存の`composition.Registry.InspectWiringSet`を一回呼び、同じ登録簿の版で調べる。第二の提供元解決器は持たない。登録簿が返す検証対象も保持する。

`Report.Verdict`の`candidate`は、宣言上の対応付け候補という意味である。契約の発行、項目定義の真正性、意味の受理、成果物の実バイト列、現在の権限、準備完了は別途確認する。`Order`はデータと明示的な作用の順序案であり、起動順序や無停止性を保証しない。

### 試作用の表現

| 要素 | 扱い |
| --- | --- |
| 局所名 | 一つの構成案で一意な`Slot.ID`。別の利用側は別の局所名を持つ |
| 項目参照 | 局所名、完全な契約識別子・版・形状、項目識別子を明示する。名前だけでは接続しない |
| 項目の多重度 | 単一、任意、列、集合を区別する。列や集合から一件を選ばない |
| 提供元の多重度 | 単一、任意、明示的に列挙した寄与の集合。任意には不在時の方針が必要 |
| 必須の監査など | `Critical`の要求は、この試作では単一の必須提供元だけを認める |
| 型の情報 | 型名、明示した単位、識別子の範囲を照合する。情報不足は未判定 |
| 数値型 | 精度制限のない整数から10進数への宣言上の拡大のみ。丸め、桁あふれ、実値の変換は扱わない |
| 機密区分 | 公開値からの接続と、同一区分どうしだけを認める。区分の階層は仮定しない |
| 実行文脈 | `Context`の項目を対応付けの行き先にできない |
| 欠損時の結果 | 行き先の契約が列挙した名前付き結果だけを参照できる |
| 寄与の順序 | 明示した順序キーで並べる。同じキーや同じ提供元の重複は拒否する |


### Semantic TypeRefの限定照合（追加Reference）

項目の`Type.SemanticRef`に、既存の`core.CanonicalID`で表すSemantic TypeRefを明示できる。両項目にRefが存在する場合はまず完全一致を要求し、同じ`std.identifier`を基礎とする`sales.order_id`と`customer.customer_id`を同一視しない。一方だけがRefを持つ場合、または同じRefに矛盾する名目的な表現が付いている場合は`unknown`として保留する。Refを持たない従来の合成Fixtureの比較結果は維持する。

**この検査は既存の`Compare`/`Inspect`に型IDの保守的な照合を足したもので、Semantic Typeの解決器ではない。** Refの宣言元・発行権限・版・fingerprint・意味の受理は検査しない。呼出元が既存のHostから正規の受理済み意味を取得したことも証明しない。したがって同じRefで`candidate`になっても、本番接続や実行の許可を意味しない。実WorkspaceのAliasを照合する試験は、参照定義の実在のみを確認する。


任意の提供元が不在でも、他の提供元で代用しない。明示した提供元が見つからない場合や、候補が曖昧な場合も不在の正常系へ置き換えない。不在の提供元の出力を別の入力が参照すれば未判定になる。不在時の方針は宣言の存在だけを調べ、実行しない。

`ProjectSamples`は、恒等の対応付けを説明するための不透明なスカラー試料を投影する。空文字、null、欠損、取得不能、未確定を区別し、対応付けた項目だけを返す。欠損時の宣言がなければ停止する。取得不能や未確定を欠損時の業務上の結果に変えない。複数の異なる欠損結果には、明示的な制御フローが必要として停止する。これは実提供元の値の検証や呼出しではない。

## 正負の事例との対応

| 事例 | この試作で確認する範囲 |
| --- | --- |
| D01・D02 | 候補の曖昧さと明示選択、登録順によらない診断。照合値の方式は未決定 |
| D03・D04 | 出力参照からの順序、提供元の撤去後の再診断、依存する側の実行案を返さないこと |
| D05 | 理由のない順序制約の拒否、データ順序と明示制約が作る循環の拒否 |
| M01・M02 | 精度を失う接続の拒否、任意から必須への接続に欠損結果を要求すること |
| M03・M10・M11 | スカラー試料の状態区別、指定した出力だけの投影、欠損時の停止 |
| M04〜M08 | 機密区分、実行文脈、単位、情報不足、契約を含む項目の同一性の検査 |
| M09 | 外部参照を伴う変換の拒否。恒等以外の演算も未評価として止める |
| C01・C02 | 明示した寄与の順序と衝突。寄与ごとの提供元は既存の登録簿で検査 |
| C03・C04 | 必須の要求の任意化、不在時の方針の欠落の拒否 |
| V01の局所例 | 必須入力の追加で既存の対応付けが不足すること。版移行の影響分析全体は未実装 |

## 実行手順

リポジトリのGo版を使い、ルートから実行する。

```sh
go test -race -count=20 ./reference/composition-io-mapping ./internal/composition
go vet ./reference/composition-io-mapping
```

実行記録は対象コミットを固定してプルリクエストに残す。ここには、将来の最新版でも合格するという記述を置かない。合成した試料の成功を、実際の提供元や本番環境の根拠にしない。

## 次の評価と制約

このパッケージは参照実装として残し、意味を扱う中核から依存しない。比較結果は、呼出し側が渡す項目情報を前提とする。登録簿の`Contract.Shape`から項目定義の真正性を導出しない。構成の検査と試料の投影が終わっても、その後に登録簿や権限が変わり得るため、実行許可に転用できない。

E2の残りは、正本の項目定義との接続、対応付けの照合値の評価、寄与の集合とデータの集合をつなぐ明示的な縮約である。集合のデータを使う対応付けは未判定とし、スカラーへの投影もしない。E3では既存の演算子へ接続し、精度、null、欠損、失敗の意味を確かめる。パラメータの所有者と優先順位、受理済みの意味への接続、静的な生成、実行世代への束縛は後続段階で扱う。

本番の移行条件は[合成Kernelの移行判定](../../plan/gate/COMPOSITION_KERNEL_MIGRATION_GATE_2026-10.md)を参照する。
