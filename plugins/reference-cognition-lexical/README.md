# Lexical choice baseline（#5807 / #5809 の比較基線）

[#5807](https://github.com/hat47x/tei-platform/issues/5807) と [#5809](https://github.com/hat47x/tei-platform/issues/5809) は、実ローカルモデルと**同一入力**で決定的な基線を比較し、適合率・誤判断率・棄権率・形式違反率を別々に測ることを求めている。このパッケージがその基線である。

ソケットを開かず、プロセスを起動せず、モデルを呼ばない。同じリクエストに対して常に同じ提案を返す。

## 何をするか

観測文と各選択肢の説明の**文字バイグラム集合の重なり**で選択肢を順位付けする。それ以上のことはしない。

- 重なりが `minSharedBigrams` 未満なら `unknown`（棄権）。
- 最上位と次位が同じ比率なら `unknown`（同点は抽選ではない）。
- 最上位が次位を `1/4` だけリードしない場合も `unknown`（僅差は判断材料不足として扱う）。

比較は整数の交差判定で行い、浮動小数の丸めが境界の判断を決めないようにしている。

## 弱さは意図である

この基線はドメイン語彙を持たない。「請求」が請求を意味することは、呼出側が与えた説明文に「請求」が含まれているから分かるだけで、語義を知っているからではない。したがって次のような場合は棄権するか誤る。

- 説明文に無い同義語で意味が表される（例: 「並び順を変えられるように」→ 機能追加）。
- 二つの目的が同じ文に同居する。

答えを既に符号化した基線は比較を無意味にする。弱いことは設計であり、結果は棄権率・誤判断率として別々に報告される。

## 使い方

`tools/reference-cognition-compare` から読む。

```sh
go run ./tools/reference-cognition-compare -baseline
```

`-baseline` は本パッケージ、`-model -provider <JSON>` は loopback の実モデルを同じケース集合で測る。

## 独立Expectedとの関係

`lexical_test.go` は採点規則を走らせる**前**に書いた日本語の期待値を持つ。基線が期待と食い違う場合は失敗にせず `t.Logf` で「lexical limitation」として記録する。期待値を基線に合わせて書き換えると比較の基準が壊れるため、食い違いは測定量として残す。

## 検査

```sh
go test -count=1 ./plugins/reference-cognition-lexical/...
go vet ./plugins/reference-cognition-lexical/...
```

## 限界

- 日本語の文字バイグラムのみ。英語の語順・語形変化は扱わない。
- 判断基準文（`constraints`）はスコアに使わない。選択肢の説明だけを見る。
- 提案だけを返す。受理・権限・適用のいずれでもない。ポートが対象・選択肢集合・basis・上限を検査する。
- 製品機能ではなく参照実装である。
